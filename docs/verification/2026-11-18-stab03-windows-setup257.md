# STAB-03. Windows Setup 3.2.257 и проверка Core OTA

На Windows 10 с Setup 3.2.255 штатная служба сталкивалась с отказом в доступе к каталогу обновлений до скачивания. Обычная перезагрузка этой ВМ также сохраняла GUID ядра, который использовался для проверки завершения прежнего Core. [Протокол 3.2.255](2026-11-18-stab03-windows-setup255.md)

В исходнике 3.2.257 служба проверяет существующие штатные каталоги SYSTEM только на чтение. После прерванного создания каталога она сверяет владельца LocalService и все ACE с фактической защищённой политикой родителя. При точном совпадении служба завершает настройку прав одного этого каталога. В нативном тесте NTFS родитель и два уже существующих потомка сохранили свои DACL.

Для машины с постоянным GUID появился второй способ подтвердить обычную перезагрузку. Требуются более высокий системный счётчик BootId, согласованные новые записи Kernel-General/12 и Kernel-Boot/20, 27 после прежней отметки и совпадение хеша старой записи System. Служба читает счётчик из реестра. При потере отмеченной записи новый запуск владельца может зафиксировать новую исходную отметку, сохранив запрет на смену версии в текущей загрузке. Схема владельца v2 читает прежние записи v1. При возврате на старую Foundation 3.2.255 та потребует собственное подтверждение. Продукт не запрашивает перезагрузку.

## Изолированный стенд

Клон Windows 10 VM217 создан из сохранённого снимка VM206 с установленной 3.2.253. На VM218 восстановлен выделенный Gateway с одной тестовой карточкой и ACK 3. Во время подготовки скрипт один раз синхронизировал время старой изолированной VM215. Смещение составило около 0,42 с. После исправления идентификатора ВМ часы VM217 сверили с фактическим UTC до назначения Setup. Квитанция `native-lab/qga-scope-clock-audit.json`, SHA-256 `137025236edd487d201ba1811ac9177fa2b6ebf8ece28afa8c60edf7bcaf4e29`.

В 15:40:23 UTC назначение подписанного Setup завершилось как `applied / setup_post_restart_confirmed`. Нативный код выхода 0. Провайдер подтвердил установку с ACK 4 и новую WSS на прежней карточке после 181,267 с связи. На клиенте совпали четыре защищённых файла. Служба 3.2.257 записала владельца по схеме v2 с исходным BootId 5 и отметкой System 433.

## Доставка Core 3.2.258

В 15:43:44 UTC Core запросил операцию `4c5015cf-11c0-4c09-aace-3230afe85518`. Служба LocalService создала каталог загрузок и файл блокировки. Журнал API подтвердил HTTP 200 для запроса штатного архива. Тем самым на установленном кандидате проверен проход через ранее блокировавшую подготовку каталогов.

При повторе в 15:48:58 UTC реальный процесс Core создал временный файл загрузки. Затем Windows Performance Recorder дважды зарегистрировал `0xC0000022` при обращении этого процесса к каталогу `updates`. В коде `EndpointUpdateAdapter._write_journal` повторно запрашивает изменение DACL родителя перед записью `endpoint_update_state.json`. Служба удалила временный файл. Назначение осталось в `requested`, сервер не получил `scheduled`, файла pending не появилось. Селектор остался на 3.2.257. Этот отдельный путь записи журнала не был покрыт предыдущей проверкой со вспомогательным адаптером. Проверки удержания pending, перезагрузки и внутреннего отката на данном артефакте не достигнуты.
