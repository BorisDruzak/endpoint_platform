# STAB-05. Восстановление чистой установки ALT 3.2.249 после недоступности Gateway

Готовый комплект `endpoint-alt-pilot-3.2.249-1.tar.gz` с SHA-256
`8ceb7cae4b0abb112071a1af8c934b3693507a9de2a6c668d2e479d1a52e6bda`
проверен на одноразовой ALT Workstation K 11.4 VM197 из снимка
`inventory-alt114-p11-rpm-ready` VM132. До прогона в госте подтвердили
отсутствие обоих RPM, активного селектора, учётных данных и журнала Setup.
Первую копию из текущего состояния VM132 отбросили на этой проверке
из-за исторической установки 3.2.183. Setup на ней не запускался.

В чистой копии использовали тот же штатный staging origin, структуру
`config.yaml` и лабораторный CA, что и в [онлайн-прогоне](2026-11-18-stab05-alt-native-249-build-upgrade.md).
Профиль и CA подготовили до запуска Setup. На закрытом мосту `vmbr144`
клиент имел один NIC и не имел маршрута по умолчанию. В отдельном
лабораторном Gateway с отдельной БД был предусмотрен один ручной допуск
для IP этой VM и точной подписанной пары RPM.

До запуска Gateway проверенный HTTPS-запрос завершился тайм-аутом
`curl 28`. Setup вернул 21, нативная транзакция RPM вернула 0,
`rpm -V` прошёл без вывода. Создался активный селектор 3.2.249
с ревизией `8a82b96ffa29994283b16d5b15afbc255d3cc469`. Исходная
операция `40a88b73-94cd-4f10-a040-d8359aea7fd6` сохранила
`pending`, `settled=false`, sequence 0 и ACK 0. Устройство,
постоянные учётные данные и `runtime-ready` ещё отсутствовали.
Core, watcher и Support были включены, но неактивны. Штатный
таймер Setup retry был включён и активен.

После запуска Gateway штатный HTTPS подтвердил `database=ok`.
`endpoint-agent-setup reconcile` вернул 21 в ожидании допуска. Через
административный API одобрили единственную заявку
`9e5cd530-4de3-4030-a89f-9837aafae415` (HTTP 204). Второй
`reconcile` завершился кодом 0. Та же операция стала
`settled=true`, `bootstrap=complete`, sequence 1 и ACK 1.
Селектор остался на исходных версии и ревизии, `runtime-ready`
появился, Core, watcher и Support запустились, retry timer отключился.
Байты config/CA, время установки и идентификатор транзакции обоих RPM
совпали между фазами.

Gateway зарегистрировал ровно одно устройство и одно событие установки
для исходной операции. Первая WSS-сессия 3.2.249
`6ccb1abe-3a15-49e8-a431-3f1811c65b18` открылась в 01:04:00.731 UTC,
следующий heartbeat записан в 01:04:30.781 UTC. В базе отсутствовали
OTA-назначения и отчёты. Пакеты установились один раз. Проверка покрывает
операторский допуск и явный штатный `reconcile` после восстановления
связи. Автоматическое завершение только по таймеру отдельно не проверяли.

Очистка подтвердила удаление VM197, диска, сетевого порта, отдельных
Gateway, worker, БД, IP и временных каталогов. Исходная VM132 осталась
выключенной. Хеши квитанций находятся в
`C:/endpoint-platform-wix-build/stab05-alt249-gateway-outage-20261118/SHA256SUMS`.
