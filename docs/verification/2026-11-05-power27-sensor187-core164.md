## Permanent Core fix and boundaries

Read-only WMI LastBootUpTime fallback is restricted to current-boot context within
the existing bounded killable native worker; it is not an OS_STARTED fact.
Primary Kernel-Boot27 classifications remain intact. Unknown earlier boots remain
unattributed, losses/resets remain visible, and current READY does not mean
continuous historical coverage. Anchored fallback record IDs protect against
reused native record numbers. No server event schema or cross-repository contract
change is needed. No Yandex workaround or new Linux media is in scope.

GitNexus query/context/impact identified WindowsPowerSource imports in runtime
application/main and upstream verification/service. Important paths were verified
in source/tests; graph absence is not used as a dependency proof.

Initial bug regression RED3 failed/3 passed. The first power suite passed80 tests
on supported Python3.12.14. Independent review identified identity instability at
the fallback/native page boundary and old header/new payload time misattribution;
five added cases reproduced these and a UTC overflow. The fix preserves fallback
provenance until the native boundary is actually crossed, accounts for query
snapshot races, validates both timestamps and treats invalid UTC conversion as
unavailable optional evidence. Final suite/release/canary results follow separately.
