## Чистая офлайн-установка до регистрации

Один запуск подписанного EXE с --quiet на каждом из VM169 и VM170
завершился фактическим кодом Setup 41 / PROVISIONING_FAILED /
PROVISIONING_UNEXPECTED без сетевого адаптера. На каждом госте журнал
содержит ровно один установленный факт с native exit 0, awaiting_enrollment,
целевым ProductCode {E1C98F94-AE97-4714-90E5-C2297B56B1A3}, исходным
коммитом кандидата и точным SHA-256 MSI. Windows Installer вернул
ProductState=5, VersionString=3.2.245 и LocalPackage с тем же SHA-256.
Селектор соответствует тому же коммиту, активный installer fence отсутствует,
четыре приватных файла ещё не созданы. Соответственно, эти квитанции
покрывают нативную установку и завершение с отсутствующей регистрацией.

Временные VM169 и VM170 штатно остановлены и удалены. Проверено отсутствие
их конфигураций и выделенных дисков. До очистки сохранены native-журнал
в виде ограниченной проекции и хеш, результат Setup и QGA-квитанции.
Общие ISO временно переданы Windows 11/офлайн-прогону на VM164.

## Офлайн-откат при отсутствии свежего WSS

Windows 10 x64, build 19045, временная VM171 из ранее принятого
лабораторного снимка VM143. Единственный запуск Setup 3.2.245 после
предпроверки READY_FOR_SETUP_UPGRADE прошёл нативную установку с exit 0.
Прежняя версия и исходник были 3.2.226 и 45e69d7ad2e9d4587351df9eeecbe95eb3cb58c7.
При отсутствии сети штатная проверка WSS не получила свежего подтверждения
и инициировала откат. Процесс завершился через примерно 9 минут 28 секунд
с фактическим кодом 67 / ROLLED_BACK / CANDIDATE_ROLLED_BACK.

После отката и обычной перезагрузки зарегистрированный MSI, селектор,
работа EndpointAgent и digest четырёх приватных файлов совпали с базой.
Digest вычислен внутри гостя по байтам, file ID и SDDL каждого файла.
Сохранены прежние события, а два новых native0 для установки кандидата и
восстановления 3.2.226 остались pending. Staged journal имеет фазу
rolled-back, активный installer fence отсутствует. SHA-256 квитанции
setup245-win10-226-offline-rollback-verified.json —
db6aa3568c157ec43314de697fbfcb5dfa4d3556fed2dcf46d65ac6d8a44f40e.
VM171, её диск и оба ISO проверки удалены, исходный снимок сохранён.

Независимый Windows 11 LTSC 26100.9457 подтвердил нативную установку
и штатный откат с точного MSI 3.2.205. Оба сценария подтверждают
откат при отсутствии подтверждения WSS.

## Совместимость с текущим production provider

Production работает на endpoint-platform-ed643cddf0f5-setup205-observer.
Список QUALIFIED_SETUP_CLIENT_VERSIONS в развёрнутом
endpoint_contracts/setup_updates.py признаёт 1.0.5, 1.0.6, 1.0.7,
1.0.8 и 1.0.11. Развёрнутый endpoint_server/setup_updates/service.py
также исключает 1.0.13 из ветки приёмки восстановления. Кандидат
содержит подписанный ClientVersion 1.0.13. Готовность текущего клиента
1.0.11 на канареечном устройстве доказывает исходное состояние, а
для нового клиента требуется совместимый provider. Кандидат
44d96b5cce415e3886328c077499bee5f3b969ec включает 1.0.13 в контракт.
Публикация и назначение в production оставлены закрытыми до обновления
provider и повторной проверки совместимости.


Normal presence и обычная приёмка 1.0.13 в 44d96b5cce41 отличаются от
узкой ветки восстановления уже начатого native exit 21.
require_recovered_target() в endpoint_server/setup_updates/service.py
по-прежнему допускает только 1.0.6, 1.0.7, 1.0.8 и 1.0.11. Обычный
canary не квалифицирует эту ветку. Активные held-операции сохраняют
исходное владение и требуют отдельной проверки точного восстановления.
