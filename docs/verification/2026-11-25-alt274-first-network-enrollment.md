# ALT 3.2.274 на чистой ALT Workstation K 11.4

25 ноября 2026 выполнена первая сетевая установка подписанного комплекта
3.2.274 на одноразовом клоне VM479. Подтверждены native exit `0`, локальный и
серверный ACK1, одна карточка, один принятый native event и свежая WSS-сессия
3.2.274 на той же карточке. В Console заявка осталась в `device_registered`.

Клон получен из остановленной VM132, снимок `inventory-alt114-p11-rpm-ready`.
До запуска Setup проверены ALT Workstation K 11.4 x86_64, отсутствие обоих RPM,
конфигурации агента, нативного состояния и активного селектора Core.
На клоне проверены обе отсоединённые подписи и все члены архива. Лабораторный
Gateway на VM142 повторно проверил точные подписанные RPM своим штатным
издателем и зарегистрировал эту пару в новой БД. У закрытого моста было два
порта, по одному на клиента и Gateway. У гостей отсутствовали маршруты по
умолчанию.
Для опыта создан отдельный CA и сертификат на ожидаемое имя после обнаружения
просроченного старого сертификата стенда. HTTPS подтверждён с проверкой имени
и закреплённого CA. Настройки доверия рабочих Gateways не менялись.

## Ход регистрации

1. Первый запуск Setup вернул `21` в ожидании ручного допуска. Проверка
   `rpm -V` для обоих установленных пакетов завершилась успешно.
2. Выделенная кампания допустила одну заявку через стандартный API. Решение
   о допуске вернуло HTTP `204`. Штатный `reconcile` завершился с кодом `0`.
3. Сервер принял ровно одно событие `installed` с последовательностью `1`,
   ожидаемыми Git SHA и хэшами пары RPM. Событие принято в 13:02:09 UTC.
   В 13:03:25 UTC WSS той же карточки был свежим, последняя активность в
   13:03:11 UTC. Оба RPM прошли `rpm -V` после регистрации. Службы Core,
   Support Access и наблюдатель каталога обновлений были активны.

Время вызовов со стороны стенда составило 31,391 с для первого Setup и 9,150 с
для `reconcile`. Первый замер включает конфигурацию лабораторной сети,
проверку TLS и RPM. Это длительности вызовов, пригодные для повторения на той
же конфигурации.

Проверен один принятый `baseline_v1`. Событий `installer_wss_verified` было
ноль. Точный Linux-клиент 3.2.274 выполняет создание запроса, опрос, получение
claim и `/agent/v1/enroll`. В этом маршруте нет вызова проверки завершения
заявки после WSS. Таким образом, установленный агент работает, а заявка
всё ещё отображается как `device_registered`. В клоне был сеанс X11 greeter,
поэтому телеметрия вошедшего пользователя осталась непроверенной.
