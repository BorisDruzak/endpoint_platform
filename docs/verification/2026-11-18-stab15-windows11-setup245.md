# Проверка Setup 3.2.245 на Windows 11

Проверка относится к подписанному кандидату Setup 3.2.245 из
`8b1e3486b2e2d1568e94785b8ae48eecb2e13527`. SHA-256 EXE
`06f6f93ea766e083f328606745497a397cbd6cfd39f49fb204670489ce0b0d5f`,
SHA-256 вложенного MSI
`a0f858363ee4f67f22faee2303dff6e03b3f5c4da81030e9f8d515f8bce4a0a4`.
На сборочной станции подписи Setup, MSI и Observer были действительными
с метками времени. Квитанция `setup245-local-build-proof.json` находится
в `C:/endpoint-platform-wix-build/setup-stability-candidate-245`, её
SHA-256 `bc29b5abafa75b062ec59700b9e27b8207207525eb67934b6ca32a126ff9bc7a`.

## Исходные образы

Первый полный клон VM164 создан из снимка VM123
`agent3282-clean-20261013`. В конфигурации этого снимка указан
`Windows_11_LTSC_Enterprise_26100.3476_x64.iso`. Перед первым запуском
временной VM удалены все сетевые адаптеры и исходные оптические
носители. Windows загрузилась до экрана блокировки. QEMU Guest Agent
не ответил, поэтому сбор результатов Setup с этого образа не состоялся.
Клон штатно выключен и удалён с диском, VM123 и её снимок сохранены.

Второй полный клон VM164 создан из снимка VM129
`inventory194-authenticode-diagnostics`. Снимок сохраняет историческую
проверку подписи Setup 3.2.194 на staging. Перед первым запуском
из конфигурации клона удалены адаптер и параметры пользовательской
сети QEMU. QGA не ответил в шести попытках. Клон штатно выключен
и удалён с диском. VM129 и её снимок сохранены.

Третий полный клон VM164 создан из снимка VM130
`applied-205-before-194` с существующей установкой. Перед первым
запуском удалены виртуальный сетевой адаптер и пользовательские
параметры QEMU. QGA подтвердил Windows 11 x86_64, build 26100.

## Предпроверка установленной версии

В Windows 11 Enterprise LTSC x86_64 build `26100.9457` зарегистрирован
один продукт Endpoint 3.2.205 и четыре службы. Физические адаптеры
отсутствовали также по данным гостя. SHA-256 EXE совпал, Authenticode
вернул `Valid` с сертификатом метки времени.

Подписанный EXE с `--preflight` выдал JSON размером 1744 байта со
схемой `endpoint_windows_fleet_preflight_v1`, целевой версией
`3.2.245` и значением `READY_FOR_SETUP_UPGRADE`. Повтор подтвердил
код выхода 0 и пустой stderr за 32,153 с. Первый запуск той же
предпроверки вернул тот же JSON. Обёртка первого замера получила
пустой `ExitCode` от `Start-Process`, поэтому код подтверждён только
повторным замером с прямым `System.Diagnostics.Process`.

В повторе совпали регистрация MSI, сведения о службах, снимки
файлов в Program Files и сравниваемые файлы идентичности. Сравнение
полного снимка состояния вернуло расхождение. Источник расхождения
не установлен, поэтому предпроверка не подтверждает неизменность
всего дерева данных.

## Штатный переход без сети и автоматический откат

Один запуск подписанного EXE `--quiet` начат в 20:35:37 UTC
17 ноября. Исходный кэш MSI 3.2.205 имел SHA-256
`689e1d9dc0dcbd0e1943e98f27cfa88cc36fe99dbf9316e58e54d4292a1fc26f`,
совпадающий с записями staging и production. MSI 3.2.245 вернул
0. Кэш зарегистрированного MSI совпал с вложенным MSI кандидата.
Журнал записал одно `installed` для 3.2.245, sequence 5,
на той же локальной привязке устройства, что и исходный sequence 4.
Событие осталось `pending`, ACK отсутствовал.

Setup выполнил автоматический откат. В 20:47:36.825 UTC, примерно
через 12 минут от запуска, записан итог
`67 / ROLLED_BACK / MSI / CANDIDATE_ROLLED_BACK`. Процессы Setup
завершились. Восстановлены регистрация и исходный кэш MSI 3.2.205,
активный Core 3.2.205 и работающая служба `EndpointAgent`.
В журнале появилось событие восстановления 3.2.205, sequence 6.
Четыре файла идентичности присутствовали после отката. После
штатной перезагрузки в 20:49:23 UTC снова подтверждены Core 3.2.205,
его работающая служба, исходная регистрация MSI и хеш кэша.
Сетевых адаптеров в клоне не было.

Истёк 300-секундный тайм-аут контроллера. Процессы Setup продолжили
работу до штатного завершения.
Код 67 подтверждён итоговым `install-result.json`. Контроллер не
успел завершить сравнение байтов и ACL четырёх файлов до и после.
Чистая установка и ремонт Windows 11, успешный переход с наблюдением
через WSS, ACK и серверная квалификация остаются открытыми.

## Отдельная попытка чистой установки и ремонта

18 ноября на pve1 создан полный временный клон VM173
stab15-win11-clean245 из чистого снимка VM123
agent3282-clean-clock-20261014. В исходном снимке указан Windows 11 LTSC
Enterprise x64 build 26100.3476. До первого запуска клона удалены сетевой
адаптер и исходные оптические носители. На гипервизоре QGA включён,
но гость не ответил на пять запросов, включая три проверки с интервалами.
Войти в гостя штатным способом без сети в этой конфигурации не удалось.
Редакция, сборка и состояние активации из гостя не подтверждены.
Подписанный Setup 3.2.245 не запускался. Чистая установка и repair
остаются открытыми до появления чистого лицензированного LTSC-профиля
с рабочим QGA или доступной авторизованной консольной сессией.

Клон остановлен. При первом удалении LVM-диск был удалён, а операция
Proxmox завершилась с ошибкой сканирования недоступного main-zfs.
После проверки отсутствия LVM-дисков из конфигурации клона удалена
устаревшая ссылка на диск и удалена сама VM. Отсутствие конфигурации
и дисков VM173 и сохранность исходного снимка подтверждены отдельно.
