# STAB-15 — ALT 11.4, чистая установка 3.2.265 и отключение после ACK1

На одноразовой VM247 из `132/inventory-alt114-p11-rpm-ready` проверены оба подписанных RPM 3.2.265-alt6 из источника `010e1fd5d3ffac17f24b7a4c50bf1dabdc2dce97`. В исходном ALT Workstation K 11.4 пакеты и прежняя идентичность отсутствовали. Выделенный Gateway на VM142 использовал свежую БД, доверенный лабораторный TLS и разовую кампанию с ручным допуском только VM247. В закрытом мосту были только два лабораторных TAP, маршруты по умолчанию отсутствовали.

Штатный Setup сначала вернул 21 в ожидании допуска. После допуска и штатного `reconcile` нативная установка записала код 0 и первый локальный ACK1 для события `61cd78fe-9acc-41ca-a73e-936ae5448bcb`. PVE запросил приостановку через 0,4 мс после получения квитанции ACK1 и подтвердил выключение в 04:49:39.920 UTC 19 ноября, через 2,54 с после её получения. Серверная проверка при выключенной ВМ подтвердила одну карточку, одно исходное событие и ACK1.

После холодной загрузки оба `rpm -V` вернули 0. Новый boot ID, прежний SHA-256 `current.json`, прежние device и generation, то же событие и локальный ACK1 подтверждены. Core запустился штатно и открыл новую WSS-сессию 3.2.265 `8fdb0c6e-5c03-4e15-9ce6-101c99829725` на той же карточке. В БД осталась одна карточка с одним событием. Это один замер чистой установки на данной конфигурации ALT 11.4.

Клон, его диск, выделенные службы Gateway, лабораторная БД и временные каталоги удалены. Исходная VM132 и общий мост сохранены.
