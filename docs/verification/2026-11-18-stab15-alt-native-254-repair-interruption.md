# STAB-15. Прерывание ремонта подписанной ALT 3.2.254

Использовали одноразовую VM221 из чистого снимка ALT Workstation K 11.4 x86_64 VM132. Установили точный подписанный комплект 3.2.254 из `448c51698b3fe2af5449fcf7a20eead8122be953`, SHA-256 архива `ea39577784f52afce5b26f01c028d342a75f65bc0749d11f8c7b82374acf1a07`. Сверили подписи, Core RPM `235e5046ab4efce481e82d3b52dfaa3bfe330a5b26c23b6bf2dde6253e2f8991` и UserSensor RPM `a97c8a5ee1c36bfad689868e850f41461f5f52f24d58d47270069980b018a15d`. Отдельный TLS Gateway подтвердил одну карточку, ACK 1 и установленный Core 3.2.254 по WSS. Перед ремонтом сохранили выключенный снимок с отключённой сетью.

## Известный native exit 0 после новой загрузки — отказ восстановления

В операции `2cc49b18-dccf-452c-a950-9be67ba4dcfa` наблюдатель дождался двух квитанций post-scriptlet, сохранённого native exit 0 и последующего `rpm -q`. По boot ID, PID, времени запуска и принадлежности дочернего процесса подтвердили владельца и прервали только координатор. После штатной перезагрузки обычный `reconcile` вернул 21. После возврата сети и успешной TLS-проверки тот же вызов снова вернул 21. Оба вызова выполнили только `rpm -q` и `rpm -V`.

Сохранились исходный operation ID, фаза `invocation_possible`, native exit 0, обе квитанции scriptlet и все семь сравниваемых полей каждого из четырёх файлов идентичности и конфигурации. Терминальная квитанция и три маркера готовности отсутствовали. Core, watcher и browser-policy остались неактивными. У них изменились только два монотонных поля времени systemd. Support штатно стартовал сам, поэтому изменились также его `ActiveState`, `SubState` и `MainPID`. В сохранённом доказательстве ни один из этих стартов ещё не запрашивался. Сравнение в `RPMBackend.recover_preparation` требует полного совпадения со снимком состояния до перезагрузки. На Gateway остались одна карточка и одно событие, без свежей WSS и без Support-туннеля.

## Неизвестный native exit после потери питания — ожидаемый hold

После возврата к выключенному исходному снимку новая операция `080da74f-309b-48c0-b904-be70bf4a8ee3` дошла до фактического дочернего `rpm -U --replacepkgs`. В этот момент остановили дочерний процесс и выключили гостя через Proxmox. После загрузки с новым boot ID обычный `reconcile` вернул 21 без запуска RPM. Сохранились байты журнала, исходный владелец, operation ID, selector, ACK 1, идентичность, ACL и содержимое конфигурации. Внешняя сверка файлов через перезагрузку учитывала inode и исключала меняющийся номер Btrfs-устройства. Оба RPM прошли отдельно запущенную проверку. Терминальная квитанция и маркеры готовности отсутствовали. После восстановления TLS Core остался неактивным, WSS не появилась, история карточки не изменилась.

Удалены VM221, диск, снимок, выделенные Gateway и PostgreSQL, дополнительный IP и временные каталоги. Исходная VM132 осталась выключенной. Квитанции и автономная проверка сохранены в `C:/endpoint-platform-wix-build/stab15-alt254-repair-interrupted`. SHA-256 `receipts.sha256` — `5a90e8cb9e511380439fa8a137bc978e35f0f190cda6e629491f7256aa6d83a8`.
