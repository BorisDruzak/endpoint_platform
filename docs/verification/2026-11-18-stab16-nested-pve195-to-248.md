# STAB-16. Bookworm 3.2.195 to 3.2.248 on nested Proxmox VE

On 18 November 2026, tested the exact Debian packages using native APT in
one disposable Proxmox VE 8.4.0 VM (VM 180, kernel 6.8.12-9-pve). The guest
was standalone, with no Corosync configuration. Its only adapter was on
`vmbr139`, which had no host address or uplink. The Gateway ran from
`44d96b5cce41` against a blank loopback PostgreSQL database migrated through
`0056_context_collection_history`. HTTPS used an ephemeral lab certificate.
APT used a signed local Bookworm repository on the guest.

| Package | SHA-256 |
| --- | --- |
| `endpoint-agent-debian_3.2.195-1deb12u1_amd64.deb` | `3e182f68c58cfd299ae06043650df002e683a3a2d8d59d57b081cedb301be7fc` |
| `endpoint-agent-debian_3.2.248-1deb12u1_amd64.deb` | `04103116872070556f4fa4e3400f3b807da40569f74aa61a74fa8807c2d8f35b` |

The fixture created one lab identity using `.248`, then established the
starting point by installing exact `.195` and confirming an active WSS session
with a heartbeat. A normal version-pinned `apt-get install` upgraded that
running `.195` service to `.248`. The service restarted (PID 2774 → 3162)
under the expected package-owned
`/usr/lib/systemd/system/endpoint-agent-debian.service.d/proxmox-health.conf`.
Installed Core identity matched source
`7bd7086a4650c9c9abd2218b2b9bbd0633235302`. Debian package audit was clean.
The enrollment identity, device credential, agent configuration and CA
matched by bytes, inode, owner, group and mode. The Gateway saw one device,
one credential and a new WSS session with a heartbeat.

After the upgrade the packaged timer, `pve-cluster` and `pveproxy` were
active. The Gateway returned a correlated `health_v1` snapshot with
`proxmox_api=ok` and `proxmox_storage=ok`, including two local storages.
The unauthenticated local Proxmox API returned HTTP 401. Quorum and
membership were reported as `unknown` on the standalone fixture.

A full reboot changed the guest boot ID and started the packaged unit
(PID 617). The same identity, credential, CA and configuration persisted.
The Gateway observed a third distinct WSS session with a heartbeat, with
one device and one credential. The PVE timer, drop-in and services were
active, the package audit remained clean, and a new correlated
`health_v1` snapshot confirmed API and storage health. The single-node
lab scope leaves multi-node quorum and membership untested.

Cleanup stopped and removed VM 180 and its thin LV, detached retained
media, removed the owned test ISO and staging directory, and confirmed
the bridge had zero ports. The retained installer ISO matched its original
SHA-256 after cleanup. All package and configuration operations took place
inside VM 180.

The operator evidence directory is
`C:/endpoint-platform-wix-build/stab16-nested-pve195-to-248-20261118`.
It contains the APT transition receipt, both PVE health checks, the reboot
receipt and the verified cleanup receipt. Exact files and digests are
listed in `SHA256SUMS`.
