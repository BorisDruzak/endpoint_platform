# STAB-15 — прерывание подписанного обновления ALT 3.2.183 → 3.2.261 до RPM

На одноразовом ALT Workstation K 11.4 проверен сбой процесса Setup после устойчивой записи намерения, до изменения установленной пары RPM. VM221 создана из выключенного лабораторного снимка VM132 `inventory-alt114-p11-rpm-ready`. Gateway, PostgreSQL и единственная лабораторная карточка были изолированы. VM107 и production не участвовали.

Исходный подписанный kit 3.2.183 из ревизии `21fc543af8d4b8b24df83f29a27e4e2eeb86c268` имел SHA-256 `c5b552afa4aa27e4df73af0ce68be4ecc88729f30baf3a70e6f9d4c8c709a3f3`. Целевой подписанный kit 3.2.261 из ревизии `788fe236bba1685526c270cc0febc11c9866697f` имел SHA-256 `0299cdd07bc6e27b2b3503db8885c587737101c8aa6c6dce91de2614343642f1`. Подписи и хеши обоих Core/UserSensor проверены по квитанциям `signed-verify-3.2.183-221.json` и `signed-verify-3.2.261-221.json`.

В первой попытке наблюдатель пропустил окно и не послал сигнал. Штатное обновление успело завершить RPM, результат сохранён отдельно. Во второй попытке на заново созданном клоне при отключённом линке наблюдатель послал один SIGKILL тому же процессу Setup после подтверждения устойчивой фазы `preparing`, остановленного Core и пустого native exit. После завершения процесса с кодом −9 байты сохранённого состояния совпали с состоянием на рубеже. Полная трасса зафиксировала 40 вызовов инструментов RPM для чтения и проверки, включая операции с отдельной временной базой проверки подписей. Транзакций установки в системной базе было 0.

На той же загрузке штатный офлайн `reconcile` вернул 0 и записал для исходной операции `d2d3baf5-045c-4d57-a878-643b564d9fd9` локальную квитанцию `not_started_recovered`. Native exit остался пустым. Reconcile не запускал RPM. Точные установленные 3.2.183, время установки, `rpm -V`, исходный селектор, идентичность, ACL, конфигурация, CA и состояния служб совпали с исходным профилем. После возврата линка та же карточка получила свежую WSS Core 3.2.183. На сервере сохранилось одно подтверждённое событие с ACK 1, события 2 не было. Support-туннель не открывался.

Обе одноразовые ВМ, их диски, выделенные процессы и базы Gateway, сетевой адрес и временные файлы PVE удалены. Локальные квитанции находятся в `C:/endpoint-platform-wix-build/stab15-alt-native-261/pre-native-pilot-upgrade`. Команда `python -B verify-pre-native.py` из этого каталога подтверждает `PASS_PRE_NATIVE_RECOVERED`. SHA-256 файла `receipts.sha256` — `d848e20c63b71c1733f2d337910277cdaf31397f34737b2fad18f5cf85a80563`.
