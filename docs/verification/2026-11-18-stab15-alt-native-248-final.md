# ALT 11.4. Историческое OTA и нативное обновление до 3.2.248

Проверка выполнена на VM187, полном клоне снимка
`inventory-alt114-p11-rpm-ready` VM132. Клиент подключён к Gateway
на VM142 через изолированный `vmbr144` без физического uplink и
маршрута по умолчанию. Для проверки были выделены отдельные API,
worker, PostgreSQL и IP. TLS проверялся по штатному имени и
существующему лабораторному CA.

## Назначение Gateway для исторического OTA

Подписанную нативную пару 3.2.183 установили с исходником
`21fc543af8d4b8b24df83f29a27e4e2eeb86c268` и зарегистрировали
через ручное разрешение только для этой пары и одного адреса.
Штатный reconcile завершился с кодом 0. Gateway записал
`installed`, sequence 1 и ACK 1. Тестовая карточка
`d4a4923b-cd3b-446e-b0cd-a515ea6491e1` создана для этого прогона.

Исторический архив 3.2.206 с SHA-256
`ebb77e1a8a2adb9730669e1ef16ccbfe6a781fbc0a2747b6fa0fd209d40ad504`
и исходником `87c2eb3a46842ea693e1a8f02059947ef51f87c1` зарегистрировали
в выделенном Gateway. Использовали сохранённую подпись авторизации.
Canary `96866325-2ab8-401d-902e-d8083507ace4` выдал назначение
`78ef21a0-7d56-46c7-9ce0-eaa6c732136b` одной тестовой карточке.
Агент сделал штатный poll, получил HTTP 200 для рекомендации и для
архива. Gateway записал `requested`, `scheduled` и один
`applied/post_restart_handshake_confirmed`, затем новую WSS 3.2.206.
Локальный штатный откат восстановил 3.2.183 и установил новую WSS
на исходной карточке.

## Точный переход 3.2.183 → 3.2.248

Перед обновлением проверили оба установленных RPM 3.2.183, активные
Core, watcher и сервис резервного доступа, локальный журнал seq 1/ACK 1
и совпадение identity с журналом.

- SHA-256 RPM Core `063db934d957426bd1b9dc28ffaf16c2e00c30864d911d1f2d266d969fd04d56`.
- SHA-256 RPM UserSensor `865b6c359d545d4092462b591ab909d2d6107fc0d050357cf4035f43b9c65298`.

Установили финальные RPM `3.2.248-alt6.x86_64` с подписью издателя
`BC24B8EE43DBB05A748E11A4343B5DA748370631`. Проверка подписи и
`rpm --test` прошли, штатный Setup и native завершились с кодом 0.
Селектор выбрал исходник `7bd7086a4650c9c9abd2218b2b9bbd0633235302`.
Четыре приватных файла, их атрибуты и историческая квитанция совпали.
Gateway сохранил исходные device ID и generation, ровно одну
карточку и два события установки. Событие перехода
`da6ee55f-52f5-47c7-bdf3-857a54c1f2f7` получило sequence 2 и ACK 2,
`bootstrap=complete`. Новая WSS 3.2.248
`9a26dcee-28ab-4a8a-a7e4-c5803adf2317` подтверждена Gateway.

Чистая установка этой же пары и UserSensor READY из локального
графического сеанса описаны в
[отчёте проверки 3.2.248](2026-11-18-stab15-alt-native-248-rearm.md).
Указания на подписанные артефакты и их хэши приведены там же.

## Штатные 900 секунд и rearm через 16 минут

На установленной 3.2.248 и ALT systemd 257.9-alt1 проверили
`StartLimitIntervalSec=900s`, `StartLimitBurst=3` и
`OnActiveSec=16min` без systemd drop-in для updater и таймера.
Три корректно сформированных запроса к историческому архиву
без установленной авторизации отклонены до остановки Core.
PID Core, селектор и четыре приватных файла сохранились.

С предварительно подписанной авторизацией следующий локально помещённый
запрос `55e32e30-7707-4ab5-9b2f-ed5782970327` остался в очереди при
`unit-start-limit-hit`. systemd запустил таймер в 21:47:36.355 UTC,
rearm в 22:03:36.840 UTC восстановил watcher, в 22:03:50.963 UTC
выполнен запрос из очереди. Оператор не сбрасывал статус и не
перезапускал watcher. История содержит ровно один успех для операции,
Gateway принял новую WSS 3.2.206
`1eaf7905-ad11-4d3e-9bfb-0647b8541ce7`. Штатный
локальный откат восстановил 3.2.248, приватные файлы и чистый
`rpm -V`, Gateway принял новую WSS 3.2.248
`2471993e-d00b-4e31-801f-0935d200ceca`.

## Принудительное выключение ВМ во время записи обновления

В повторе с подписанным историческим архивом запрос
`5541d26e-72d7-4fe3-9b55-0491073b58e3` сохранялся в очереди,
владелец остановки Core был записан для текущего boot ID, Core был
`inactive` и активный селектор ещё указывал на 3.2.248. В этот момент
тест приостановил cgroup updater. Proxmox выполнил `qm stop`
в 22:05:20 UTC, подтвердил выключение и загрузил ВМ с новым boot ID.

После загрузки Core, watcher и независимый Support поднялись штатно.
В 22:05:46.954 UTC updater завершил тот же запрос, история содержит
один успешный результат. Старый маркер владельца и pending отсутствуют.
Локальные device ID, generation, четыре приватных файла, sequence 2 и
ACK 2 совпали. Gateway увидел WSS 3.2.206
`c9be6784-ae88-4aad-a85d-a003103f9c35`. После штатного отката проверены
исходник 3.2.248, `rpm -V`, активные сервисы и новая WSS 3.2.248
`a1029313-66b1-43fb-a773-b2093668f438` на той же карточке.

Назначение через Gateway проверено на историческом переходе
3.2.183 → 3.2.206. Для таймера и внезапного выключения применён
доверенный архив 3.2.206 с локальной постановкой запроса.
Точная пара 3.2.248 прошла проверку в нативном канале RPM.

## Независимый резервный SSH

На чистой VM189 установили те же подписанные RPM 3.2.248.
Выделенная лабораторная БД разрешила одну ручную регистрацию только
для точной пары и адреса VM189. Gateway утвердил запрос
`1adc7193-f621-4cd5-b2f2-bfc5cfc71cbe` с HTTP 204, а штатный reconcile
вернул 0. Для этой проверки создана отдельная карточка
`16204a59-b061-4058-97ec-9248ec844ec1`.

Через штатный API выдали ограниченную шестью минутами политику
на эту карточку. Туннель работал через отдельный SSH broker с
закреплённым ключом Gateway. Оператор проверял закреплённый ключ
устройства. С Core, updater service и watcher в состоянии `inactive`
два отдельных SSH-подключения в 22:16:13 и 22:16:21 UTC выполнили
команду проверки с UID 0. Независимый SupportAccess оставался
активен. Штатный revoke закрыл порт. После штатного запуска Core и
watcher проверены активность всех трёх сервисов, чистый `rpm -V` и
новая WSS 3.2.248 `3740b800-6841-4731-8ac1-aa5d3c506d78`.

## Квитанции и очистка

Квитанции лежат в `C:/endpoint-platform-wix-build/stab15-alt-final-183-248-20261118`.

- Историческое назначение и откат подтверждают `altfinal-gateway-ota-assignment.json`, `altfinal-ota206-gateway-applied.json` и `altfinal-183-restored.json`.
- Точный нативный переход подтверждают `altfinal-native183-to-248.txt`, `altfinal-native183-to-248-selector.txt` и `altfinal-native183-to-248-gateway.json`.
- Таймер и выключение подтверждают `altfinal-248-full-timer-journal.txt`, `altfinal-power-before-cut.json`, `altfinal-power-hypervisor.txt`, `altfinal-power-systemd-journal.txt`, `altfinal-rate-and-power-ops.json` и `altfinal-power-final-wss.json`.
- SSH подтверждают `altfinal-ssh-independent.txt`, `altfinal-ssh-revoke-negative.txt` и `altfinal-ssh-restored-wss.json`.

VM187, промежуточная VM188, VM189 и их диски удалены. Удалены
временные API, worker, БД, SSH broker, учётные записи и ключи SSH,
дополнительный IP и рабочие каталоги. На VM142 исходные Gateway,
PostgreSQL и worker работают. VM107, VM132 и VM142 сохранены.
Точные подписанные артефакты остались на рабочей станции.

На тех же RPM отдельно проверены пять отказов при нехватке места и inode,
повтор обновления после снятия ограничения и восстановление исходного
Core. [Проверка STAB-10](2026-11-18-stab10-alt-native-248-resources.md)
