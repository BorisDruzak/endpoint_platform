# STAB-16. Состояния службы при переустановке DEB 3.2.248

Проверены точные выпущенные для лабораторной квалификации DEB из ревизии
`7bd7086a4650c9c9abd2218b2b9bbd0633235302`. Новых сборок не делали.

| Suite | SHA-256 |
| --- | --- |
| Debian 12 Bookworm | `04103116872070556f4fa4e3400f3b807da40569f74aa61a74fa8807c2d8f35b` |
| Ubuntu 24.04 Noble | `28ae0ee313b9d853d4dc8f62db44bdc161392ffdfea9035e75788cdf513741e5` |

Извлечённые `preinst`, `postinst`, `prerm` и `postrm` совпали побайтно
с проверенными пакетами соответствующей suite из линии 3.2.205, включая
сохранённые DEB ревизии `2993dd69`. Это подтверждает код управляющих
скриптов исторических прогонов. Исполнение этих скриптов для 3.2.248
проверяли отдельно. Приёмка предыдущего обновления и WSS после
перезагрузки описана отдельно для [Bookworm](2026-11-18-stab16-bookworm195-to-248.md) и [Noble](2026-11-18-stab16-ubuntu-noble197-to-248.md).

В каждой одноразовой VM без сетевого адаптера скрипт проверял
хеш пакета и встроенную идентичность штатного Core. Для воспроизводимого
сбоя временный drop-in подменял `ExecStart` службы на локальный процесс,
отключал автоматический рестарт и снимал условия, требующие enrollment.
Состояния создавались штатным `systemctl`, пакет переустанавливался
через `dpkg -i`. Такой профиль проверяет взаимодействие dpkg и systemd.
Сетевой сеанс и поведение Core при сбое в этот профиль не входят.

| Исходное состояние | Ожидаемое состояние после переустановки |
| --- | --- |
| `failed`, `enabled` | `active`, `enabled`, PID ненулевой |
| Вручную остановлена, `enabled` | `inactive`, `enabled`, PID 0 |
| `inactive`, `disabled` | `inactive`, `disabled`, PID 0 |
| `inactive`, `masked` | `inactive`, `masked`, PID 0 |

Для отдельной проверки `configure` службу запустили вручную в состоянии
`disabled`. После `dpkg --unpack` ожидались `unpacked`, PID 0 и
блокировка с `Resume=yes`. Временный `policy-rc.d` вернул 102 на пути
восстановления ручного запуска. Первый `dpkg --configure` должен
вернуть 1 и оставить `half-configured`, PID 0 и запись `Resume=yes`.
После удаления hook повторный `dpkg --configure` должен вернуть
`installed`, восстановить активную службу с новым PID и сохранить
`disabled`. Записи перехода должны исчезнуть, а `dpkg --audit` и
`dpkg -V` остаться чистыми.

Обе проверки завершились кодом 0 и подтвердили все ожидаемые состояния.
Debian VM 182 использовала systemd 252 и dpkg 1.21.23, Ubuntu VM 183
использовала systemd 255 и dpkg 1.22.6. При повторном `configure` PID
стал 1497 на Debian и 2393 на Ubuntu. Пробный drop-in и тестовый hook
удалены внутри обеих VM. Для Ubuntu потребовалось дождаться запуска
guest agent после повторного старта VM. Core и управляющие скрипты
пакетов перед проверкой оставались побайтно неизменными.

Очистка завершилась кодом 0. ВМ 182 и 183, их диски, оба ISO и отдельный
каталог временных файлов удалены. Квитанции управляющих тестов,
сравнения скриптов и очистки сохранены в
`C:/endpoint-platform-wix-build/stab16-deb248-lifecycle-20261118`,
их SHA-256 перечислены в `SHA256SUMS`.
