# STAB-16 — штатное обновление Ubuntu Noble 3.2.197 → 3.2.205

18 ноября 2026 года. Этот профиль дополняет матрицу действующей
production-версией Ubuntu. В матрице уже есть подписанная лабораторная
установка 3.2.205 на Ubuntu, переход с 3.2.192, а также переход
Bookworm 3.2.195 → 3.2.205 на вложенном Proxmox VE 8.4.

Действующий production Noble InRelease скачан по HTTPS с утверждённым CA.
gpgv подтвердил подпись закреплённого издателя
840AC80D602970C76C282E6DD02C861F8B636743. Проверены Valid-Until,
SHA-256 файла Packages из подписанного InRelease и SHA-256 файла DEB
из Packages и записи production-выпуска.

Временная VM176 загружена из ранее проверенного Ubuntu cloud image
04e8f2461a16a44e78a370284471f29616cdd9baf1893df25807b71f985b6c94.
QGA подтвердил Ubuntu 24.04.5 LTS x86_64, 6.8.0-147-generic.
VM без сетевого адаптера. Gateway и PostgreSQL слушали только loopback.
Оба неизменяемых DEB внесены в новый подписанный лабораторный file: APT.
Политика production APT и узлы production использованы только как
источник подписанных публичных данных.

Лабораторная идентичность выдана одноразово через известный bootstrap
целевого 3.2.205; Gateway подтвердил 201/204 и один credential. Для
подготовки исходного состояния стенд штатно установил .197 при остановленной
службе, затем запустил штатный активный сервис .197 и дождался его свежего
WSS heartbeat. Этот профиль проверяет установленную .197 с обычной
идентичностью и APT-обновление, отдельная первичная регистрация старым
bootstrap и история эксплуатации production-хостов здесь не воспроизводятся.

На активно работающей .197 запущен apt-get install точной 3.2.205.
APT завершился с кодом 0, dpkg audit пуст, проверка пакета не выявила
расхождений кроме ожидаемой лабораторной настройки origin в conffile.
Systemd MainPID сменился, сервис активен без drop-in, бинарь сообщает
ожидаемый source. Gateway подтвердил новую WSS-сессию с heartbeat
на той же карточке и с единственным credential. Сравнение четырёх файлов
сохранности учитывало байты, inode, uid, gid и режим доступа.


После обычной перезагрузки VM сохранились тот же credential и все
сравниваемые атрибуты. Gateway принял третью свежую WSS-сессию
на той же карточке, Core 3.2.205 и heartbeat. До и после APT-update
boot ID совпадал, после перезагрузки стал новым. Все три session ID
различны. На время проверки сохранялись ровно одна карточка и один credential.

Первая попытка подготовки тестового Gateway остановилась до установки
агента из-за прав прохода к изолированному PostgreSQL runtime. Попытка
сохранена; права каталога в лаборатории исправлены, штатный unit агента
испытан без изменений. VM176, её диск, два ISO и временные лабораторные
ключи удалены после проверки зависимостей. Публикация целевого DEB и
реальное производственное обновление относятся к отдельным шагам выпуска.
