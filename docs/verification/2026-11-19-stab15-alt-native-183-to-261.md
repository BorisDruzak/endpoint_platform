# STAB-15. Прямое нативное обновление ALT 3.2.183 → 3.2.261

На чистой одноразовой ALT Workstation K 11.4 x86_64 VM221 из снимка VM132 установили историческую подписанную пару 3.2.183-alt6, совпадающую по хешам с нативной парой четырёх работающих пилотных устройств. До первой загрузки клона удалили настройки сети и ISO. Для испытания подключили один NIC к закрытому мосту с отдельным TLS Gateway и БД. На Gateway допущена одна новая лабораторная карточка.

| 3.2.261 | `788fe236bba1685526c270cc0febc11c9866697f` | `018ab4d1c3abc4619c4d59cfa74da1e9655971a1876a247ca7393cde8a05f1cd` | `f02933902e73d103af6d35d575b8502af1fa2937ffd643e33244ed6a5c3b3510` |

Хеши комплектов 3.2.183 и 3.2.261 — `c5b552afa4aa27e4df73af0ce68be4ecc88729f30baf3a70e6f9d4c8c709a3f3` и `0299cdd07bc6e27b2b3503db8885c587737101c8aa6c6dce91de2614343642f1`. Проверили подписи архивов и манифестов издателя `BC24B8EE43DBB05A748E11A4343B5DA748370631`, совпадение вложений и подписи обеих пар RPM. Прямой вызов `endpoint-agent-setup upgrade` из комплекта 3.2.261 вернул 0. Нативный журнал сохранил exit 0, селектор переключился на 3.2.261, `rpm -V` прошёл для обоих пакетов до и после обновления.

На той же карточке и в том же поколении получены ACK 1 для 3.2.183 и ACK 2 для 3.2.261 с правильным предыдущим событием. После обновления свежая WSS-сессия `7cb313e0-4e16-4d18-b860-0e3d9fd1cec0` доставила один завершённый `health_v1`. Содержимое, inode, владельцы, режимы и ACL четырёх файлов конфигурации, CA и идентичности совпали. Состояния активности и включения Core, watcher, browser-policy и Support сохранились. Обновление добавило статический неактивный rearm timer. Туннель Support не открывался. Прогон выполнен в одной загрузке, без OTA и промежуточной версии.

Удалены VM221, диск, выделенные Gateway и БД, дополнительный IP и временные каталоги. Квитанции в `C:/endpoint-platform-wix-build/stab15-alt-native-261/direct183`. SHA-256 `receipts.sha256` — `4906c369acc9484de77ec618e8f6a858486d2443b26868aa1ff5e30c2d96ef68`.

## Сравнение поставки Support

Из 55 файлов Support в каждом подписанном Core RPM 51 совпал побайтно, включая все поставляемые нативные библиотеки. Различаются ELF, unit systemd, метаданные ревизии и контейнер `base_library.zip`. Распакованное содержимое ZIP и все модули PYZ совпадают. Единственный изменившийся элемент встроенного архива ELF — `support_access_service`, который в .261 сохраняет причину HTTP 409 при регистрации. Unit сохраняет прежний `ExecStart` и добавляет условие, блокирующее старт через systemd при наличии `support-pending`.

В [реестре .183](../releases/linux-3.2.183-native.json) зафиксированы три отдельные записи с `strict_actual_root_ssh=true`. Поле `stopped_core_updater_ssh_seconds` у них равно 93,39, 99,38 и 113,59 с соответственно. Эти значения — длительности из реестра. Число выполненных SSH-команд из них не следует. Для .261 отдельная проверка на штатном broker остаётся открытой. При полной готовности Setup требуется подтвердить канал с закреплённым ключом хоста при остановленном Core, закрытие доступа после отзыва политики и свежую WSS прежней карточки после запуска Core.

Автономный `verify-support-payload-183-261.py` принимает два Core RPM в порядке .183, .261 и проверяет закреплённые SHA-256 перед извлечением. Скрипт и JSON-квитанция находятся в `C:/endpoint-platform-wix-build/stab15-alt-native-261`. SHA-256 манифеста `support-payload-183-261.sha256` — `5a8c14a0ebe498ee510fbc96a36a44831d75ea26184c0da857aaf8dca63d6602`. Для запуска нужны Python с PyInstaller и `tar` с поддержкой RPM (bsdtar).
