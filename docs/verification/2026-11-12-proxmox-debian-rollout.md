## Пилот и развёртывание

На pve1 зарегистрировали точный DEB 3.2.193 через Console. На хосте 86
интерфейсов. Сборщик сети передавал до 64 записей при ограничении Gateway в 32,
из-за чего ошибка валидации завершала процесс агента. В 3.2.194 сборщик
сохраняет интерфейс основного маршрута, отмечает усечение, а ошибки
валидации обрабатываются как результат отдельной команды.

После обновления pve1 через APT до 3.2.194 оба файла идентичности совпали
побайтово. PID служб Proxmox сохранились. Контроллер принял пять профилей
и зафиксировал резервное WSS-подключение. Затем установили 3.2.194
на pve2 и pve3.

| Узел | Адрес | ID устройства | PID в проверке 443 → 8443 → 443 |
| --- | --- | --- | --- |
| pve1 | 10.83.1.11 | `980ce52d-cf14-4a97-bde3-de6730cf2cae` | 3443358 |
| pve2 | 10.83.1.12 | `15bab1a0-63f2-4e80-bd1f-985f2c87456d` | 3168653 |
| pve3 | 10.83.1.13 | `adda8e85-c4f3-4133-b2d7-a383ce1c3375` | 3866048 |

Для каждого узла Console показывает зарегистрированное устройство и
одно использование отдельной кампании. Gateway принял Core 3.2.194,
`baseline_v1`, `health_v1`, `inventory_v1`, `network_v1` и `session_v1`.
На 8443 Nginx зафиксировал WSS с HTTP 101 для всех трёх адресов.
Проверки TLS на 443 и 8443 вернули HTTP 200, запрос `/admin` из управляющей
сети вернул HTTP 403. После тестов временные правила удалены, активные сессии
вернулись на 443, кворум составил три узла, `pveproxy`, `pvedaemon` и
`pvestatd` работали. Перезагрузку гипервизоров в рамках пилота не выполняли.
