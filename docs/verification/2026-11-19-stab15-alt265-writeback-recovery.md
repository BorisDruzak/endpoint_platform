# STAB-15. ALT Setup 3.2.265 после ошибки записи

На изолированной ALT Workstation K 11.4 VM242 один штатный переход со старой подписанной пары .183 на .265 завершил транзакцию RPM с кодом 0. При последующей синхронизации отдельной лабораторной файловой системы ядро вернуло `EIO`. Setup вернул 21. На той же загрузке штатный `reconcile` также вернул 21. И локально, и в выделенной БД на этот момент сохранились исходная карточка и ACK 1. [Точные подписанные пакеты](2026-11-19-stab15-alt265-post-ack2-power.md)

| Наблюдение | Результат |
| --- | --- |
| Исходная операция | `d58781f9-b1a2-41ed-8b51-2b91a4d1535e` |
| До перезагрузки | Оба целевых RPM установлены. Запись для файловой системы RPM-базы прошла. Синхронизация файловой системы конфигурации вернула `EIO`. Операция осталась незавершённой. |
| Обычная перезагрузка | Обработчик systemd записал исходный ID операции, попытку и идентификатор загрузки. Гостевой агент закрыл соединение во время команды перезагрузки. Новая загрузка подтверждена изменением boot ID и сохранённой записью обработчика. |
| Штатный reconcile после перезагрузки | Код 0, запись обеих файловых систем успешна. Повторного запуска установки RPM не наблюдалось, времена установки обоих пакетов сохранились. Проверка файлов обоих RPM прошла. |
| Учёт на Gateway | Ровно один ACK 2 для исходной операции. Байты идентичности, владельцы, права и селектор сохранились. Core .265 открыл новую WSS `8459c3f2-6488-438f-9ee3-a661df5458d7` на прежней карточке. |

Проверка использовала отдельный одноразовый диск для файловой системы конфигурации. Подготовительный запуск стендового сценария потребовал исправления до получения квитанции ошибки. В зачётном запуске зафиксированы реальный ответ ядра и один вызов установки RPM. Временную VM242 с обоими дисками и выделенный Gateway удалили. Тест относится к указанной паре и к ошибке записи на этой файловой системе.

Автономная проверка связывает 18 файлов квитанций по SHA-256, включая результаты Setup, сведения о загрузках, RPM, селекторе и события на сервере.
