# STAB-04. Восстановление ALT 3.2.251 после ограничения запусков systemd

Испытание проведено на одноразовой ALT Workstation K 11.4 VM196 из снимка `inventory-alt114-p11-rpm-ready` VM132. Проверка `rpm -q` перед установкой подтвердила отсутствие обоих пакетов Endpoint. Единственный NIC находился на закрытом мосту без маршрута по умолчанию. Отдельный Gateway `192.0.2.147` и отдельная PostgreSQL на loopback допускали только тестовый IP `192.0.2.196`. TLS проверялся по штатному лабораторному имени и CA.

Точный комплект 3.2.251 имеет SHA-256 `c8c2b6b2feff3f26fd51165a5b0b8d6e99a0f99d754e4e72b950d4433a82c945`, исходник `10a0a1c33bef241aaee0937b243b7954b67c6525`. SHA-256 Core RPM — `e03b37cf74a13f981b3f1b0eb0b8c4e3dcc8b9e94a5e1db57cb026ac38d7465a`, UserSensor RPM — `e32c905f9cf24e7ff02b9febf7a66897f0d40e20d51eb5d8e278bc373d6d550a`. Нативная установка и `reconcile` вернули 0, обе проверки `rpm -V` прошли. Единственная новая карточка получила ACK 1 и WSS 3.2.251.

Файлы watcher, updater, rearm, Core unit и shell-обвязка побайтно совпадают с 3.2.248. Упакованный `launcher`, который shell вызывает для preflight и применения, отличается. Поэтому результат ниже получен на 3.2.251. [Предыдущая проверка 3.2.248](2026-11-18-stab15-alt-native-248-final.md)

## Отключённый watcher

На готовой системе штатный `systemctl disable --now endpoint-agent-update.path` отключил watcher. При отдельном запуске установленный `endpoint-agent-update-rearm.service` был пропущен по `exec-condition` в 10:38:07.826255 UTC. Состояния `disabled/inactive` и PID работающего Core сохранились. Штатный `enable --now` вернул исходное состояние перед проверкой таймера. После выгрузки завершившегося oneshot `systemctl show` не сохранил параметры выполненного `ExecCondition`. Решение systemd подтверждает журнал.

## Включённый watcher

Тайминги установленных unit: окно 900 секунд, три запуска и rearm через 16 минут. Временные настройки systemd и сброс счётчика не применялись. Использован прежний проверенный архив 3.2.206 `ebb77e1a8a2adb9730669e1ef16ccbfe6a781fbc0a2747b6fa0fd209d40ad504` и исходная подпись издателя. Три запроса до установки файла авторизации отказали до остановки Core. После установки авторизации четвёртый локальный запрос остался в очереди при `unit-start-limit-hit`. Gateway не выдавал OTA-назначений.

По журналу гостя timer активировался в 10:38:58.953213 UTC. Через 960,295 с он запустил rearm, который восстановил watcher. В исходной операции `55e32e30-7707-4ab5-9b2f-ed5782970327` сохранилась одна успешная запись. Watcher выбрал 3.2.206, а Gateway увидел WSS `afced0fe-7795-47d2-a8d7-ed2b592529be` на прежней карточке. Затем отдельный штатный локальный запрос отката вернул селектор 3.2.251. Оба RPM снова прошли `rpm -V`, Core и watcher работали, четыре защищённых файла совпали. Gateway принял новую WSS `68956ee5-7054-44fc-8365-50c033c2a9e9` на той же карточке. В журнале установки осталось одно событие с ACK 1.

Квитанции сохранены в `C:/endpoint-platform-wix-build/stab04-alt251-rearm`. Удалены VM196, диск, отдельные API/worker/БД, адрес `192.0.2.147` и временные каталоги. VM132 оставалась выключенной, исходные службы VM142 активны. SHA-256 манифеста квитанций `10d2c9f7388e775c21478bf60e6342d03dff7afaf44c88b00d261a7a3315ae47`.
