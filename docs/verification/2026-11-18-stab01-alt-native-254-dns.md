# STAB-01 на подписанном ALT 3.2.254

На одноразовой VM220 из чистого снимка `inventory-alt114-p11-rpm-ready` VM132 проверили ALT Workstation K 11.4 x86_64. Перед первой загрузкой у клона удалили пользовательскую сеть QEMU и ISO, затем подтвердили отсутствие NIC, маршрутов по умолчанию и обоих Endpoint RPM. Для регистрации и команд подключили один NIC к закрытому мосту. Выделенные TLS Gateway и PostgreSQL обслуживали одну тестовую карточку. Установка получила ACK 1 и достигла полной готовности.

Комплект с SHA-256 `ea39577784f52afce5b26f01c028d342a75f65bc0749d11f8c7b82374acf1a07` проверили по подписям архива и манифеста издателя `BC24B8EE43DBB05A748E11A4343B5DA748370631`. Исходник `448c51698b3fe2af5449fcf7a20eead8122be953`. SHA-256 Core RPM `235e5046ab4efce481e82d3b52dfaa3bfe330a5b26c23b6bf2dde6253e2f8991`, UserSensor RPM `a97c8a5ee1c36bfad689868e850f41461f5f52f24d58d47270069980b018a15d`. Перед и после команд `rpm -V` прошёл для обоих установленных пакетов, PID лаунчера оставался 3497.

Gateway передал две обычные одношаговые операции `dns.resolve` по одной WSS-сессии Core 3.2.254. Локальный resolver принял два запроса к `hold.stab01.test` и оставил их без ответа. Пока первая команда была `running`, вторая уже имела статус `delivered`. Сервер зарегистрировал новый heartbeat в 17:31:11.191331 UTC и ACK `APPLIED` для политики без сбора данных в 17:31:11.225728 UTC. Отказ первой команды сохранён в PostgreSQL в 17:31:14.918374 UTC. Следующая команда разрешила `ok.stab01.test` в той же сессии. Обе получили по одному терминальному результату, `failed` и `succeeded`. От первого DNS-пакета до запроса второй команды прошло 10,055 с по монотонным часам гостя. Метки из клиентского ACK и часы БД не вычитали друг из друга.

Первая попытка выявила выключенные флаги сетевых примитивов в отдельном Gateway, поэтому команды оставались в очереди. После истечения этих назначений включили штатные флаги только на тестовом Gateway и ограничили разрешённые DNS-цели суффиксом `.stab01.test`. На .254 проверены очередность, heartbeat, policy ACK и выход из системного ожидания. Остановку службы при активном worker проверяли ранее на установленной .205-alt7. Нагрузочное заполнение очереди и отдельный shutdown в этом прогоне не выполнялись.

VM220, её диск, временные каталоги, выделенные процессы API, worker, PostgreSQL 55458 и дополнительный адрес Gateway удалены. Исходная VM132 осталась выключенной. Квитанции и проверка сохранены в `C:/endpoint-platform-wix-build/stab01-alt254-native`. SHA-256 `receipts.sha256` — `ee6f308d1a8e2021cac3f3fc10aeef8c89a01f5ded85547c595be919f76764f8`.
