# Прерывание MSI при ремонте Windows Setup 3.2.259

VM222, Windows 10 19045.2006. Исходное принятое офлайн-состояние `setup259-reinstall-ack7-offline`, exact MSI `9b30625fd8568b4d45c76fbb9c712b146c4a70d958e7c6449185b96ab4564943` и подписанный Setup `75b3a6fa5ac88f03f8061e88431741cd283c689d5297541b63e2b4a64e973b02`. Только у тестового Core отсутствовала регистрация SCM, как в штатном сценарии ремонта. Сетевой линк был отключён весь прогон.

Новая нативная операция `4b1289af-c6b8-498f-b147-c5d5c52f8f0c` в защищённом fence прошла prepared → msi-starting → msi-executing, sequence 2, с точным MSI и тремя процессами msiexec. Подтверждённое наблюдение 18:02:01.1058681 UTC, запрос паузы 18:02:01.811182298, QEMU приостановлен 18:02:02.669071575, выключен 18:02:04.569619675. Операция прежнего staged обновления осталась accepted и не являлась ремонтной транзакцией.

После включения Windows записала Kernel-Power 41 и EventLog 6008. Fence пережил выключение с прежними operation/sequence и хешем. После проверки отсутствия работающего Setup/Windows Installer один раз повторили штатный точный Setup `--quiet` для продолжения, без повторного удаления SCM. Итог 18:06:06 UTC — `21 / MSI / INSTALL_FAILED / MSI_EVIDENCE_FAILED`. Старый fence сохранился, Core не зарегистрирован, updater Disabled, BrowserPolicy Stopped. Точный MSI и селектор .259, агрегат четырёх файлов идентичности, последний доставленный ACK7 совпали. Нет новой записи жизненного цикла агента и нет WSS. Возобновление считается удержанным.

После единственного операторского запуска Windows Installer записал две пары 1033/11707 для Endpoint Agent, обе записи 1033 указывают версию .259 и статус 0. Это две наблюдаемые завершённые операции на уровне журнала Windows Installer в рамках одной попытки продолжения. Привязать их к двум отдельным запускам точного MSI по этим данным нельзя. Ни один результат не закрыл защищённый fence. Повторов теста с отключением питания и повторного запуска Setup после кода 21 не было.

Граница в исходнике .259. Recovery Prepare сохраняет существующий fence seq2. Перед Process.Start wrapper повторно проверяет ID транзакции и SHA пакета. В ветви восстановления подтверждённый ProductState=5 допускает REINSTALL=ALL. Следующая запись fence выполняет внутренняя MSI Custom Action после InstallInitialize. Поэтому оставшийся seq2 сам по себе не исключает новый Process.Start, а две пары событий не устанавливают число отдельных запусков. Проверены Install-EndpointAgentCanary.ps1 строки 3533–3584, Services.wxs строка 157 и installer_transaction_bridge.py строки 896 и 934–935 из точного исходника 85f78df48ca891956e614cd6afd63eb03c22dea2.
