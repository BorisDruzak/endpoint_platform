# STAB-15 power loss with unknown RPM result on ALT 3.2.251

The expected recovery hold passed on disposable ALT Workstation K 11.4 x86_64 VM196, using the exact signed 3.2.251 kit SHA-256 `c8c2b6b2feff3f26fd51165a5b0b8d6e99a0f99d754e4e72b950d4433a82c945`. The closed TLS fixture had one manually approved device, installation ACK 1 and established WSS.

- With its NIC down, stock Setup began repair of the installed exact pair. The observer matched the coordinator's PID, start time, boot ID and process group, and observed its actual child `/usr/bin/rpm -U --replacepkgs`. It froze that child to pin the fault boundary. The operation `886d5f0f-f716-4281-b9e1-844fc6392451` was in `invocation_possible` with an unknown native exit, no completed post-scriptlet receipt and no runtime-ready. Proxmox stopped the guest abruptly at 06:38:05 UTC. The fresh guest boot ID differed.
- Stock Setup `reconcile` returned 21. The syscall trace showed no RPM execution by reconcile. The persisted native journal bytes, original owner PID, start time and old boot ID were unchanged. The result stayed unknown, the operation unsettled, and the terminal receipt and runtime-ready marker remained absent. Separate read-only RPM queries and both package verifications succeeded. This recovers evidence while retaining the hold described in the [native Setup runbook](../runbooks/LINUX_NATIVE_SETUP.md#same-version-repair-on-alt-114).
- The device, generation, previous event, sequence, ACK 1 and selector matched baseline. Configuration, CA, enrollment identity and device credential retained their inode numbers, owners, modes, byte hashes and ACL hashes. The first automated comparison included the reboot-dependent Btrfs device number. A comparison of the preserved before/after evidence confirmed that this was the only changed filesystem field. The original operation was never rerun.
- Once the lab link returned, canonical TLS health passed. Core stayed inactive and the Gateway retained one enrollment request, one installation event and the existing card. No fresh WSS appeared. The documented path leaves an unknown transaction pending for explicit diagnosis.

VM196, its disk, its dedicated Gateway units, database, IP alias and temporary staging were removed. Source VM132 remained stopped and VM142's original three services remained active. Signed inputs were retained. The receipts are under `C:/endpoint-platform-wix-build/stab15-alt-native-251-power-loss`.
