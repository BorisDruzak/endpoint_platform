## Карточка испытания для каждой строки

| Сценарий | Свидетельство |
| --- | --- |
| Чистая установка | Точные байты и подпись, штатное завершение установщика, одна регистрация, свежий WSS и нужный серверный профиль. |
| Upgrade | Штатный канал доставки, исходный и итоговый селекторы или версии пакета, терминальное состояние задания, свежий результат после переключения. |
| Same-version repair | Восстановленная служба и пакетные файлы, штатный запуск, прежний UUID и отсутствие новой регистрации. |
| Rollback | Применён точный предыдущий артефакт, восстановлена версия, агент пришёл на прежнюю карточку и отправил свежие данные. |
| Reboot | Изменился boot ID, службы стартовали по политике, свежий WSS и профиль приняты контроллером. |
| Offline remove/reinstall | Сохранены предназначенные для удержания данные. После возврата связи приняты прежний UUID и свежие события. |
| Принудительный обрыв | Отдельные точки до и после начала native-операции. Записать исход, восстановление служб и селектора, состояние журнала, владельца операции и отсутствие повторной установки. |
| Credentials, origin и CA | Сравнить UUID, наличие и хеши приватных файлов, основной и резервный origin, доверенный CA и действующую конфигурацию. Содержимое приватных файлов в отчёт не включать. |
| UserSensor и независимый support | Для профилей, где они предусмотрены, подтвердить свежее событие реального пользователя и фактическое действие support с остановленными основным агентом и updater. Зафиксировать восстановление сервисов и закрытие временного доступа. |

Перед расширением rollout сверьте точное совпадение образа, исходной версии и
подписанного артефакта с карточкой испытания. Для Windows Full Setup дополнительно
проверьте действующую серверную qualification и preview охвата. Для Linux
сверьте канал RPM, APT или Core OTA и область регистрации. Сценарии со статусом
«открыт» оставляют соответствующую пару вне расширения.

## Локальная проверка Debian 12

14 ноября 2026 года на автономном LXC 127 с Debian 12.12 amd64, glibc 2.36
и systemd 252 собран стендовый `endpoint-agent-debian_3.2.205-1deb12u1_amd64.deb`.
SHA-256 — `708d72a065aa011a4071a549d15614a8cdd9e56684051f3e260d09c2388eb646`.
Замороженный Core и метаданные DEB указали одну ревизию
`4f419ba187a5aac0e5ab720482033003405c1c48`, Python 3.12.16 и PyInstaller 6.19.0.
Исходный `3.2.193-1deb12u1` имел SHA-256
`cc8ebf1da12d9f8106dd1ab627cd1517a3801c63c1315cf19524c54370b967fc`.

- Сборка с `umask 077` сначала упала на правах каталога `DEBIAN`. После исправления
  тест с настоящим `dpkg-deb` проверил права распакованных директорий, runtime-файлов
  и сохранение symlink. Всего на Debian прошли 25 тестов упаковки и APT.
- Через штатный `dpkg -i` прошли обновление активной службы с 3.2.193, её
  восстановление после управляемого сбоя при переустановке той же версии
  и откат на 3.2.193. Ручная остановка и маска сохранились при переустановке.
- После удаления и установки без сети файлы синтетической идентичности, CA
  и конфигурации совпали по SHA-256. Оба файла идентичности сохранили владельца
  службы и права `0600`. После перезапуска контейнера с новым boot ID служба
  запустилась, а Core от её пользователя подтвердил ревизию.
- LXC запретил штатному unit создать пространство монтирования с кодом
  `226/NAMESPACE`. Для лабораторного прогона применялся временный override
  директив изоляции и пути CA. После прогона он снят, исходный DEB 3.2.193
  возвращён, служба отключена, контейнер остановлен. В контейнер добавлены
  штатные зависимости `curl` и `libcurl4` для установки нового пакета.

Артефакт остался на стенде и проверен повторно в отдельной VM.

## Проверка штатного Debian unit в VM

VM137 без сетевого адаптера, Debian 12.15 amd64, ядро
`6.1.0-54-cloud-amd64`. SHA-256 Debian genericcloud qcow2 —
`d8533680bab71d55bb181c95d60a1f394614aac761b73f1a6930938ecc0f9f54`.
Хеш SHA-512 образа также совпал с опубликованным Debian `SHA512SUMS`.
Для питания, консоли и передачи тестовых файлов использовался QEMU guest agent.

- Штатный APT проверил `InRelease` локального Bookworm-репозитория, подписанного
  отдельным ключом стенда и привязанного через `signed-by`. Чистая установка
  3.2.205 создала пользователя службы. Через APT прошли откат на 3.2.193,
  обновление на 3.2.205, восстановление включённой failed-службы переустановкой
  той же версии, сохранение ручной остановки и маски, удаление и установка
  без внешней сети. Оба DEB совпали по SHA-256 с артефактами из проверки LXC.
- Штатный `endpoint-agent-debian.service` запустился с `LoadCredential`,
  `ProtectSystem=strict`, `PrivateTmp=yes` и `NoNewPrivileges=yes`. Единственный
  локальный drop-in агента задавал путь к файлу с тестовым DNS-адресом.
  В VM без сетевого адаптера отключили ожидание `systemd-networkd-wait-online`.
- Локальный TLS-пир проверил bearer и UUID заранее подготовленной тестовой
  идентичности, принял WSS hello и heartbeat после установки, отката,
  обновления, ремонта и после перезапуска VM с новым kernel boot ID.
  Сравнение SHA-256 конфигурации, CA и обоих приватных файлов прошло.
  В hello поле `boot_id` содержало `http-pull`. Перезагрузка подтверждена
  значением из ядра VM и новой записью heartbeat в журнале текущей загрузки.
- После повторной распаковки 3.2.205 VM принудительно выключена в состоянии
  `unpacked`. После старта `dpkg --audit` показал один распакованный пакет.
  `dpkg --configure endpoint-agent-debian` вернул статус `installed`;
  повторный аудит был чист, конфигурация и идентичность совпали, локальный
  TLS-пир принял heartbeat. Проверена точка между стадиями `unpack` и `configure`.
  После проверки VM остановлена и сохранена как стенд.

## Завершение заявки и обрыв при настройке пакета

В отдельной пустой базе на VM137 повторена регистрация того же DEB через
реальный Gateway. Сохранённое при создании заявки доказательство передано
в `POST /api/v1/enrollment/requests/{request_id}/verify`. API вернул
`completed`, повторил этот статус при повторном вызове и вернул 404 для
постороннего доказательства. В базе остались
одна регистрация, одна завершённая заявка и одна запись аудита
`installer_wss_verified`. Приняты пять профилей контекста, включая
`baseline_v1`, необходимый для завершения заявки.

При повторной установке того же DEB временный `policy-rc.d` задержал
`postinst` в точке перезапуска службы. Перед принудительным выключением
VM процесс `dpkg --configure` работал, состояние пакета было
`half-configured`. После старта состояние сохранилось. Временный hook
удалён, повторный `dpkg --configure endpoint-agent-debian` вернул
`installed`, а `dpkg --audit` завершился без замечаний. Хеши файлов
идентичности, CA и конфигурации совпали, Gateway принял новый heartbeat
на той же карточке.

При обычном интервале обслуживания worker удалил конверт повторной
доставки после истечения срока и записал один `enrollment.delivery_expired`
с источником `periodic_cleanup`. Заявка осталась `completed`, в Gateway
сохранилась одна открытая сессия со свежим heartbeat. VM после проверки
штатно остановлена.

Отдельно через `gpgv` проверен подписанный стендовый `InRelease`. Он
связывает хеш `Packages` с версией DEB, SHA-256 пакета, исходной ревизией,
версиями Python и PyInstaller. Из триады тестов упаковки, provisioning и
API регистрации на Python 3.12 прошли 56, один тест требует POSIX и пропущен
на Windows.

### Обрыв во время распаковки

В VM137 ограничили только процесс `dpkg --unpack` через `CPUQuota=5%`.
В момент появления файла Core с суффиксом `.dpkg-new` заморозили cgroup
операции. Перед принудительным выключением подтвердили живой процесс dpkg,
`FreezerState=frozen`, временный файл размером 425 984 байта и состояние
пакета `half-installed`.

После старта сменился kernel boot ID, а `dpkg --audit` потребовал
переустановку. Команда `dpkg -i` с тем же DEB, вновь сверенным по SHA-256,
вернула состояние `installed`. `dpkg --audit` и
`dpkg -V endpoint-agent-debian` завершились без вывода. В каталоге Core
не осталось файлов `.dpkg-new` или `.dpkg-tmp`. Установленный Core от
пользователя службы сообщил версию и встроенную ревизию стендового пакета.
Хеши пары идентичности, CA и конфигурации совпали. Gateway записал heartbeat
в новой сессии, открытой после начала переустановки, на той же карточке.
В базе по-прежнему одна завершённая заявка, одна регистрация и одна
открытая сессия. VM штатно остановлена.

Открыты прямое подтверждение доставки, публикация через production APT
и приёмка отдельных профилей Ubuntu и Proxmox.

### Замена исполняемого файла и авария при загрузке Python

В VM138 распакованы копии обоих точных DEB в отдельные каталоги. Загрузчик
PyInstaller 6.19.0 прочитал таблицу архива 3.2.205 и модуль `aiohttp.client`.
После атомарной замены файла по тому же пути на 3.2.192 чтение с прежней
таблицей вызвало тот же `zlib.error: incorrect header check`. Новый загрузчик
прочитал модуль 3.2.192, SHA-256 бинарника после замены совпал с оригиналом.
Так воспроизведён механизм сбоя. В исходном прогоне журнал показал запуск
PID 2714 до отметки dpkg `unpacked` для 3.2.192. Точный момент замены файла
относительно чтения архива в том прогоне не измерялся.

На штатной службе повторены откат 3.2.205 → 3.2.192 и обновление обратно
с остановкой до `dpkg -i` и запуском после. Обе версии отправили heartbeat
TLS-пиру с первой попытки, `NRestarts=0`. Проверки `dpkg -V` и
`dpkg --audit` не обнаружили расхождений. Идентичность, CA и конфигурация
совпали по SHA-256, VM штатно остановлена. Исправление переходов со
службой, запущенной в момент установки, остаётся открытым.

### Проверка запрета запуска во время распаковки

В VM138 собран отдельный лабораторный DEB с новыми maintainer scripts
и прежним проверенным Core. SHA-256 DEB —
`2555c7a0e357ef287b486b8238da150ff0b253fc1fda8272dde0173020c65fdf`.
Входящий `preinst` остановил работающую службу 3.2.192. После

Запрет сохранился после перезагрузки. `dpkg --configure` снял запрет,

### Debian 12 с новыми скриптами и прерыванием postinst

Из чистого коммита `2993dd6956ceea179b7c05d41139708c4f22f967`
пересобраны Core и DEB 3.2.205-1deb12u1 на Debian 12 с Python 3.12.16
и PyInstaller 6.19.0. SHA-256 пакета —
`d73388d3596fa4e5cc379fa04606da1196106a5633004785e488ccec26ba5d2e`.

На сборочном Debian прошли 37 тестов DEB и APT.

APT начал переустановку поверх работающей версии 3.2.205 с прежними
maintainer scripts. Временный `policy-rc.d` приостановил `postinst`
перед запуском Core. В этот момент пакет был `half-configured`, PID
службы равен нулю, а запись `.endpoint-package-resume` уже содержала
`Resume=yes`. VM принудительно выключили.

После запуска сменился kernel boot ID. Состояние `half-configured` и
запись намерения сохранились. После удаления тестовой задержки
`dpkg --configure` завершил установку и очистил оба файла перехода.
`dpkg --audit` и `dpkg -V` прошли без вывода. Хеши идентичности, CA

### Ubuntu 24.04.5 из точного коммита и потеря питания при распаковке

Core и DEB `3.2.205-1ubuntu1` собраны в VM138 из чистого коммита
`2993dd6956ceea179b7c05d41139708c4f22f967`, Python 3.12.3 и
PyInstaller 6.19.0. SHA-256 DEB —
`73ec08da10a5cf506502bff7c671f524b10585be21e8da35d215aeccfc9430b9`.
Штатный APT принял подписанный стендовым ключом индекс Noble с
`signed-by`, прочитал совпадающие версию, SHA-256 и поля provenance.
Переустановка того же номера версии заменила предыдущий лабораторный DEB
точной сборкой из коммита. Проверка установленного Core от пользователя
службы подтвердила ревизию. PID изменился, `NRestarts=0`, локальный
TLS-пир принял heartbeat.

Во втором прогоне VM принудительно выключена при замороженном
`dpkg --unpack` в состоянии `half-installed`. На момент выключения
существовал временный файл Core `.dpkg-new` размером 32 768 байт,
служба имела `MainPID=0`, а запрет запуска был записан на диск.
После смены kernel boot ID пакет остался `half-installed`.
Ручной запуск службы получил `ConditionResult=no`, PID остался нулевым.
Переустановка того же DEB после проверки хеша вернула `installed`,
удалила оба файла перехода и запустила Core с `NRestarts=0`.
`dpkg -V`, `dpkg --audit` и сверка хешей идентичности, CA и
конфигурации прошли. TLS-пир принял новый heartbeat, VM штатно
остановлена. Для Ubuntu остаются открытыми регистрация и приёмка
профилей на настоящем Gateway, а также публикация через production APT.
