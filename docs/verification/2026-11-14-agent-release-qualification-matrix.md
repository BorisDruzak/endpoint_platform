## Карточка испытания для каждой строки

| Сценарий | Свидетельство |
| --- | --- |
| Чистая установка | Точные байты и подпись, штатное завершение установщика, одна регистрация, свежий WSS и нужный серверный профиль. |
| Upgrade | Штатный канал доставки, исходный и итоговый селекторы или версии пакета, терминальное состояние задания, свежий результат после переключения. |
| Same-version repair | Восстановленная служба и пакетные файлы, штатный запуск, прежний UUID и отсутствие новой регистрации. |
| Rollback | Применён точный предыдущий артефакт, восстановлена версия, агент пришёл на прежнюю карточку и отправил свежие данные. |
| Reboot | Изменился boot ID, службы стартовали по политике, свежий WSS и профиль приняты контроллером. |
| Offline remove/reinstall | Сохранены предназначенные для удержания данные. После возврата связи приняты прежний UUID и свежие события. |
| Принудительный обрыв | Отдельные точки до и после начала native-операции. Записать исход, восстановление служб и селектора, состояние журнала, владельца операции и отсутствие повторной установки. |
| Credentials, origin и CA | Сравнить UUID, наличие и хеши приватных файлов, основной и резервный origin, доверенный CA и действующую конфигурацию. Содержимое приватных файлов в отчёт не включать. |
| UserSensor и независимый support | Для профилей, где они предусмотрены, подтвердить свежее событие реального пользователя и фактическое действие support с остановленными основным агентом и updater. Зафиксировать восстановление сервисов и закрытие временного доступа. |

Перед расширением rollout сверьте точное совпадение образа, исходной версии и
подписанного артефакта с карточкой испытания. Для Windows Full Setup дополнительно
проверьте действующую серверную qualification и preview охвата. Для Linux
сверьте канал RPM, APT или Core OTA и область регистрации. Сценарии со статусом
«открыт» оставляют соответствующую пару вне расширения.

## Локальная проверка Debian 12

14 ноября 2026 года на автономном LXC 127 с Debian 12.12 amd64, glibc 2.36
и systemd 252 собран стендовый `endpoint-agent-debian_3.2.205-1deb12u1_amd64.deb`.
SHA-256 — `708d72a065aa011a4071a549d15614a8cdd9e56684051f3e260d09c2388eb646`.
Замороженный Core и метаданные DEB указали одну ревизию
`4f419ba187a5aac0e5ab720482033003405c1c48`, Python 3.12.16 и PyInstaller 6.19.0.
Исходный `3.2.193-1deb12u1` имел SHA-256
`cc8ebf1da12d9f8106dd1ab627cd1517a3801c63c1315cf19524c54370b967fc`.

- Сборка с `umask 077` сначала упала на правах каталога `DEBIAN`. После исправления
  тест с настоящим `dpkg-deb` проверил права распакованных директорий, runtime-файлов
  и сохранение symlink. Всего на Debian прошли 25 тестов упаковки и APT.
- Через штатный `dpkg -i` прошли обновление активной службы с 3.2.193, её
  восстановление после управляемого сбоя при переустановке той же версии
  и откат на 3.2.193. Ручная остановка и маска сохранились при переустановке.
- После удаления и установки без сети файлы синтетической идентичности, CA
  и конфигурации совпали по SHA-256. Оба файла идентичности сохранили владельца
  службы и права `0600`. После перезапуска контейнера с новым boot ID служба
  запустилась, а Core от её пользователя подтвердил ревизию.
- LXC запретил штатному unit создать пространство монтирования с кодом
  `226/NAMESPACE`. Для лабораторного прогона применялся временный override
  директив изоляции и пути CA. После прогона он снят, исходный DEB 3.2.193
  возвращён, служба отключена, контейнер остановлен. В контейнер добавлены
  штатные зависимости `curl` и `libcurl4` для установки нового пакета.

Артефакт остался на стенде и проверен повторно в отдельной VM.

## Проверка штатного Debian unit в VM

VM137 без сетевого адаптера, Debian 12.15 amd64, ядро
`6.1.0-54-cloud-amd64`. SHA-256 Debian genericcloud qcow2 —
`d8533680bab71d55bb181c95d60a1f394614aac761b73f1a6930938ecc0f9f54`.
Хеш SHA-512 образа также совпал с опубликованным Debian `SHA512SUMS`.
Для питания, консоли и передачи тестовых файлов использовался QEMU guest agent.

- Штатный APT проверил `InRelease` локального Bookworm-репозитория, подписанного
  отдельным ключом стенда и привязанного через `signed-by`. Чистая установка
  3.2.205 создала пользователя службы. Через APT прошли откат на 3.2.193,
  обновление на 3.2.205, восстановление включённой failed-службы переустановкой
  той же версии, сохранение ручной остановки и маски, удаление и установка
  без внешней сети. Оба DEB совпали по SHA-256 с артефактами из проверки LXC.
- Штатный `endpoint-agent-debian.service` запустился с `LoadCredential`,
  `ProtectSystem=strict`, `PrivateTmp=yes` и `NoNewPrivileges=yes`. Единственный
  локальный drop-in агента задавал путь к файлу с тестовым DNS-адресом.
  В VM без сетевого адаптера отключили ожидание `systemd-networkd-wait-online`.
- Локальный TLS-пир проверил bearer и UUID заранее подготовленной тестовой
  идентичности, принял WSS hello и heartbeat после установки, отката,
  обновления, ремонта и после перезапуска VM с новым kernel boot ID.
  Сравнение SHA-256 конфигурации, CA и обоих приватных файлов прошло.
  В hello поле `boot_id` содержало `http-pull`. Перезагрузка подтверждена
  значением из ядра VM и новой записью heartbeat в журнале текущей загрузки.
- После повторной распаковки 3.2.205 VM принудительно выключена в состоянии
  `unpacked`. После старта `dpkg --audit` показал один распакованный пакет.
  `dpkg --configure endpoint-agent-debian` вернул статус `installed`;
  повторный аудит был чист, конфигурация и идентичность совпали, локальный
  TLS-пир принял heartbeat. Проверена точка между стадиями `unpack` и `configure`.
  После проверки VM остановлена и сохранена как стенд.

## Регистрация Debian 12 через Gateway

На той же VM137 запущены Gateway и отдельный worker из ревизии
`fe5b441586830498a122b5657f073159bc610853`, Python 3.12.16,
PostgreSQL 15.20 и схема `0052_inventory_installation`.
SHA-256 архива исходников —
`fd40b560c5fea95dcc9bee96e13121551b39d8daa8a8827817a269d03920a83c`.
SHA-256 списка установленных зависимостей —
`af6e0c42f2fc5454cd878fcde846b751558d884ac45776cfa7b647b64f881325`.
Gateway и PostgreSQL слушали только loopback. Staging DNS-имя разрешалось
в `127.0.0.1` внутри VM и проверялось отдельным сертификатом стенда.

- Локальный запуск Gateway добавлял в реестр точную пару версии и SHA-256 DEB
  для VM137 и адреса `127.0.0.1`. Штатные HTTP-обработчики приняли запрос
  Debian, вход администратора, одобрение и выдачу claim. Замороженный Core
  выполнил обмен через штатный first-boot режим с systemd credentials.
  Полученные файлы с правами `0600` перенесены в каталог штатной службы.
  После успешной передачи локальный claim удалён.
- PostgreSQL подтвердил одно устройство, одну действующую учётную запись
  устройства, один использованный claim, одно использование кампании и одно
  событие регистрации. Статус заявки остался `device_registered`, конверт
  повторной доставки ещё присутствовал при контрольном чтении. Отдельный
  вызов подтверждения готовности заявки в этом прогоне не выполнялся.
- До перезагрузки Gateway сохранил heartbeat и принял `baseline_v1`,
  `health_v1`, `network_v1` и `session_v1`. После перезагрузки сменились
  kernel boot ID и WSS session ID. Предыдущая сессия закрыта, новая сохранила
  heartbeat через 30,06 секунды после подключения. На той же карточке
  осталась одна открытая сессия, число регистраций не изменилось.
  Хеши пары идентичности, CA и конфигурации совпали. VM остановлена.

Открыты завершение заявки и подтверждение доставки, сбой внутри распаковки
или настройки пакета, публикация через production APT и приёмка отдельных
профилей Ubuntu и Proxmox.
