# STAB-02. Результат уже запущенной команды на ALT 3.2.266

На ALT Workstation K 11.4 подписанная .266 неверно определила, успела ли команда начаться до потери питания. Проверка проводилась на VM259/260, в изолированной сети на одной лабораторной карточке. Пакеты, протокол и исполняемый файл Core соответствовали проверенной локальной сборке. Исполнитель выполнял штатную команду `health_v1`.

| Этап | Наблюдение |
| --- | --- |
| До отключения | В транзакции SQLite наблюдались одна команда `running`, пустая таблица резервирования старта и пустая очередь результатов. В группе службы Core был один дочерний процесс с аргументом `--gateway-command-worker`. Группа процесса 2067 приостановлена после его запуска. Наблюдатель повторно проверил PID, родителя, время старта, состояние процесса и журнал. |
| Отключение | Возраст показания с поправкой часов составил 13,6 мс. Через 24,1 мс гипервизор подтвердил остановку vCPU. На Gateway была одна начатая команда без результата. Идентификатор в запросе и локальном журнале совпал. Сам PID связан с командой по единственности выполнявшегося задания и исполнителя. |
| Первая загрузка | Core доставил `AGENT_COMMAND_INTERRUPTED_BEFORE_START`. Для этого случая требуется `AGENT_COMMAND_OUTCOME_UNKNOWN`. Gateway сохранил один результат, ноль снимков и передал точное подтверждение. Локальная очередь опустела. |
| Следующая загрузка | В кадрах отправки команды, разрешения старта, результата и ACK один UUID `1abb44be-bd00-4234-9953-b130c63d0478`. Второй доставки на исполнение и второго результата не обнаружено. |

При повторной проверке совпали все 38 SHA-256 первого прогона. Парные снимки `alt266-stab02-paired` восстановлены вместе. Отдельно сохранён холодный снимок второго опыта до запуска Core. Содержимое диска этого снимка при диагностике не извлекалось. ## Проверка объяснения

В .266 локальный журнал выбирает ответ по резервированию, которое он видит при восстановлении. Пассивный наблюдатель записал ошибочный ответ ещё до обработки на Gateway. На синтетической БД с SQLite 3.53.1 и `journal_mode=DELETE` откат подтверждённого удаления удалось воспроизвести, смоделировав потерю обновления каталога в режиме FULL. При EXTRA SQLite потребовал синхронизацию каталога, и в рамках этой модели удаление сохранилось. Такой результат согласуется с нативной ошибкой. Доказательства фактического отката конкретного файла журнала на VM259 нет. [Синтетический опыт](C:/endpoint-platform-wix-build/stab02-alt266-synthetic-vfs/verified.json) · [Документация SQLite](https://sqlite.org/pragma.html#pragma_synchronous)

В комплекте ALT находится SQLite 3.53.3. На отдельной синтетической БД в той же гостевой Btrfs подтверждены DELETE и исходный FULL. После восьми прогревочных итераций выполнены 40 измерений на режим. Для commit отметки старта медиана и p95 в режиме FULL составили 5,57 и 13,28 мс, в режиме EXTRA — 7,16 и 17,87 мс. Это длительность отдельной записи. Время ответа команды по сети измеряется отдельно.
