# STAB-03. Windows Setup 3.2.259 и Core OTA 3.2.260

Установленный 3.2.257 смог получить архив с Gateway, но перед созданием pending служба повторно запросила запись прав на уже защищённый каталог журналов. В 3.2.259 журналы операции и терминального отчёта используют ту же строгую проверку родителя, что и загрузчик. Запись одного журнала не создаёт каталог загрузок. [Нативное воспроизведение на 3.2.257](2026-11-18-stab03-windows-setup257.md)

## Удержание операции и обычный Restart на Windows 10

Одноразовый клон VM219 начинал с 3.2.253 и ACK 3. VM218 обслуживала только эту карточку в отдельной сети и отдельной БД. В 16:22:30 UTC штатный Setup завершился с кодом 0. Gateway принял 3.2.259 с ACK 4 после 181,212 с связи. Установленный MSI совпал с подписанным артефактом, четыре защищённых файла сохранились. [Карточка выпуска и контрольные суммы](../releases/windows-3.2.259-candidate.json)

При первом запуске после обновления с 3.2.253 новая служба впервые записала владельца по схеме v2. Для предыдущего запуска подтверждения остановки ещё не было. Это состояние возникло при штатном Setup до получения назначения Core OTA. На этой ветви обработка ожидающего назначения завершилась после обычной перезагрузки.

## Правило восстановления каталогов

При повторном запуске служба может завершить создание `updates` или `updates/downloads`, если владельцем является LocalService и все унаследованные записи прав точно совпадают с проверенным штатным родителем. Сверяются идентификаторы получателей, права, типы записей и флаги наследования. При несовпадении операция остаётся на прежней версии до скачивания. Для уже защищённого штатного каталога SYSTEM достаточно проверки на чтение.

Повтор 13 профильных проверок прошёл на Windows. Среди них штатный каталог SYSTEM, прерванное создание обоих каталогов, неверный владелец, права или наследование, недоверенный родитель и reparse point. В тесте на NTFS применялись настоящие DACL и дескрипторы файлов. Для этой временной папки SID владельца LocalService подставлялся в тесте. Нативная служба на стенде отдельно прошла штатные пути получения и записи обновления. [Предыдущая нативная проверка подготовки каталогов](2026-11-18-stab03-windows-setup257.md)

## Потеря связи и автоматический откат

После сохранения принятого положительного результата на стенде восстановили снимок ожидающей операции. Gateway выключили, а сетевой интерфейс Windows отключили на гипервизоре. После обычного Restart Core 3.2.260 запустился в 16:33:52 UTC. Подтверждение запуска от Gateway отсутствовало. В 16:43:52 UTC по истечении штатных 600 секунд updater записал `rolled_back / launcher_rolled_back` для исходной операции и сообщил версию 3.2.259.

На стенде снова работал Core 3.2.259. Байты селектора совпали с состоянием до испытания, хеш кэшированного MSI и контрольная сумма четырёх защищённых файлов сохранились. Остались прежние ACK 4 и событие установки. Запись перехода снята. Для доставки отчёта после возврата связи на диске остались pending и локальный результат. Этот экземпляр держали отдельно от БД с уже принятым положительным результатом.

В первой версии скрипта наблюдения была ошибка синтаксиса PowerShell 5. После исправления наблюдатель прочитал состояние работающего 3.2.260 и исходные файлы терминального результата. Для испытания использованы Windows 10 build 19045 и лабораторная карточка. [Хеши квитанций двух исходов](../releases/windows-3.2.259-candidate.json)

## STAB-09. Прерванная загрузка и обновление в одной загрузке Windows
