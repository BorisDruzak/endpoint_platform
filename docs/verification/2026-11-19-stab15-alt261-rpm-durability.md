# STAB-15. Долговечность файлов подписанных RPM ALT 3.2.261

Проверили одну пару прогонов на собственной VM239 без NIC. Полный
клон создан из `VM132/inventory-alt114-p11-rpm-ready`. Оба прогона
начались с одного выключенного снимка `offline-rpm-baseline` без
установленного Endpoint. В обоих случаях установили штатной командой
`rpm -U` точные `endpoint-agent` и `endpoint-agent-user-sensor`
3.2.261-alt6.x86_64 из `788fe236bba1685526c270cc0febc11c9866697f`.
`rpm -Kv` подтвердил обе подписи, `rpm -U --test` прошёл до снимка.
Штатный Linux Setup, Gateway, enrollment и ACK в этом контроле не
использовали.

В обоих прогонах `rpm -U` и `rpm -V` вернули 0 до отключения.
Хеши Core ELF, системного unit Core и пользовательского unit Sensor
совпали между прогонами. RPM 4.13.0.1 вывел `_dbpath=/var/lib/rpm` и
пустые подстановки `_pkgverify_level` и `_flush_io`.
`/opt`, `/usr` и rpmdb имели один mount ID 28, `0:26`,
`/dev/sda2[/@]` на Btrfs. Параметры QEMU диска обеих веток:
raw local-lvm, `cache=none`, `aio=io_uring`, `detect-zeroes=on`.
Явного `discard=unmap` в команде не было.

| Ветка | От получения readback на PVE до запроса паузы | Пауза и подтверждение выключения 19.11 UTC | После загрузки |
| --- | ---: | --- | --- |
| `sync --file-system /opt` | 10,005 с | 01:26:26.883 / 01:26:27.702 | Обе NEVRA, `rpm -V` 0, 0 строк отличий, все три SHA-256 совпали |
| Без дополнительного sync | 10,004 с | 01:28:01.319 / 01:28:02.150 | Обе NEVRA, `rpm -V` 2, 234 строки отличий, все три проверяемых файла отсутствовали |

Вызов syncfs завершился кодом 0 за 275,279 мс. Служебный шаг с ним
занял 292,435 мс. Гостевые и PVE метки записаны отдельно. Равенство
интервалов задано от получения readback гипервизором, задержка доставки
квитанции со стороны гостя различалась. В первой постзагрузочной
квитанции диагностический `printf` для кода `rpm -q` выдал предупреждение.
Обе NEVRA были прочитаны, фактический код отдельного `rpm -V` и
хеши записались. Для второй ветки диагностическая строка исправлена.

Наблюдаемая разница подтверждает, что успешный readback штатных
RPM-файлов до обрыва в этой конфигурации недостаточен для гарантии
сохранения. Один парный прогон не устанавливает причину исходного
повреждения VM221, где файлы сохранились с нулевой длиной. Синхронизацию
нижних уровней хранения и эффект добавления барьера в штатный Setup
отдельно не проверяли.

VM239, её диск, снимок и временный PVE-каталог удалены после сверки
зависимостей. VM132, VM221, VM142 и production не затрагивали.
Квитанции сохраняют исходные и последующие boot ID, NEVRA, SHA-256 и
тайминг. SHA-256 проверенного индекса —
`506bf3478de764ffcedf5d86ba3eec527fca7c57ed46eafa1719d262442d3c9e`.
