# STAB-15. Штатный переход ALT 11.4 с .183 на .265 и возврат

19 ноября 2026 года на одноразовой VM249 с ALT Workstation K 11.4 x86_64 проверен переход `3.2.183-alt6 → 3.2.265-alt6 → 3.2.183-alt6`. Каждый переход выполнил штатный `endpoint-agent-setup upgrade` из целевого подписанного комплекта. Для возврата исторический Setup .183 принимает `upgrade`, а его точный источник использует нативный `rpm -U --oldpackage`. Отдельная лабораторная БД приняла события 1, 2 и 3 на одной карточке `aac7f156-b8d5-4402-ab7c-7b8b2d2a2290` в одном поколении `bec3a093-8fd6-4105-8045-3be1180f330c`.

| Этап | Результат |
| --- | --- |
| Исходная .183 после загрузки | Оба RPM прошли проверку. Gateway принял ACK 1 и свежую WSS `57665c4f-c280-4f9e-86e2-a50666f379e9`. |
| Обновление до .265 | Процесс Setup и нативная операция вернули 0. Селектор показывает точную ревизию .265, оба `rpm -V` вернули 0. |
| Штатная перезагрузка .265 | `systemctl reboot --no-block` и смена boot ID. Селектор, ACK 2, карточка, поколение и хеши с правами четырёх защищённых файлов сохранились. Оба `rpm -V` вернули 0. `health_v1` `ca50f1d6-86c3-425f-a88a-71cd71aaba68` завершился через новую WSS `cf86e107-d814-4afe-a4a1-d3d1b2e566de`. |
| Операторский возврат до .183 | Процесс Setup и нативная операция вернули 0. После второго штатного reboot оба `rpm -V` вернули 0. Селектор побайтно совпал с исходной .183, сохранились та же карточка, поколение и защищённые файлы. Gateway подтвердил ACK 3 и свежую WSS `77c340de-3585-4818-9544-09e094cc3fd5`. |

В госте после обновления наблюдался экран входа X11. Данных из пользовательского сеанса Plasma нет. В Gateway отсутствовали назначения и отчёты OTA. Прогон относится к локальному штатному обновлению и операторскому возврату точных подписанных пар.

Проверены отделённые подписи обоих архивов и манифестов по отпечатку издателя `BC24B8EE43DBB05A748E11A4343B5DA748370631`, SHA‑256 вложений и совпадение манифестов. Стенд использовал только закрытый мост `vmbr144`, отдельный TLS Gateway и свежую БД, один допуск на VM249. Начальный сценарий развёртывания ожидал индекс хешей, который предыдущий сценарий создавал на шаге возобновления. Индекс восстановлен из проверенных входов до вызова Setup. Первая базовая проверка опередила установление WSS. Следующая проверка зафиксировала WSS до запуска обновления. QGA отключался при обеих штатных перезагрузках. Новые boot ID подтверждены после восстановления канала.

После локальной и серверной сверки квитанций удалены VM249, её диск, временные службы и БД на VM142, дополнительный адрес и рабочие каталоги. Проверки очистки подтвердили отсутствие VM249, диска и временного каталога. VM132 осталась остановлена, VM142 — запущена, в `vmbr144` остался только `tap142i0`.

Обе автономные проверки прошли. Сумма SHA-256 индекса 37 файлов равна `ffa9f8497dc4fc07e0ac7e0229f3e4758263617e149e6160a35d861fbbf12414`.
