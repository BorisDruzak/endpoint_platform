# Проверка выпуска Windows и ALT 25 ноября 2026

## Действующие источники

Сверка выполнена в production PostgreSQL в транзакции read-only. Версии
нативной установки взяты из последнего принятого события на каждой активной
карточке, включая отключённые устройства. Присутствие WSS не заменяет
подтверждение установки. Числа относятся только к карточкам с принятым
native-событием.

| Платформа и источник | Принято | Из них с действующей сессией | Значение для квалификации |
| --- | ---: | ---: | --- |
| Windows 3.2.205 | 8 | 8 | Основной опубликованный источник. Нужен прямой сетевой переход на фактических профилях Windows 10 и 11. |
| Windows 3.2.264 | 2 | 2 | Действующие пилоты. Сохранить отдельный маршрут и сверить точный профиль. |
| Windows 3.2.186, .188, .192, .193, .196, .203, .245 | 14 | 11 | Сверить применимость штатного прямого перехода, моста или удержания для каждого профиля. |
| ALT 3.2.183 | 10 | 9 | Основной опубликованный комплект. Сохранить подтверждённые переходы и профиль штатного отката. |
| ALT 3.2.265 | 1 | 0 | Действующий офлайн-пилот. Учитывать как исходный профиль. |

Windows 3.2.253 присутствует в каталоге скрытых установщиков. На момент
сверки отсутствовали действующие кампании для этого номера, заявки
регистрации, назначения и принятые установки. Для .273 и .276 не обнаружены
также записи каталога установщиков. Чтобы исключить переход с промежуточного
кандидата, подтвердите отсутствие доступности вне Lab и полный сброс
испытанного профиля. ALT .270 зарегистрирован в нативном каталоге.
Карточек с последней принятой установкой .270 в этом срезе не было.

Windows Full Setup revision 21 остаётся на паузе с целью .205. Одно
назначение на .205 находится в `recovery_required`. Квалификация другого
профиля не снимает это состояние.

## Результат исправления ALT Setup

Два теста воспроизвели частичный файл под итоговым именем при симуляции
`ENOSPC` после первых записанных байтов. После исправления для RPM и Setup
тесты подтвердили отсутствие итогового файла после ошибки и повторное
сохранение исходных байтов. Выборка из тестов нативного жизненного цикла,
параметров стенда, RPM и комплекта дала 143 успешных теста и 3 пропуска на
Windows.

На изолированной ALT Workstation K 11.4 проверены функции из коммитов
`88e0809a2cd6b7ccbbc646310426aebc6127c2f1` и
`3f1dc26ac0d50bab39dab4c9e04cb026f6086d54`. В приватном пространстве
монтирования tmpfs размером 64 КиБ вернула фактический `ENOSPC` при
копировании 192 КиБ. Исходный код оставил частичный конечный файл для обоих
входов. После исправления конечные пути отсутствовали. Повтор на tmpfs
размером 1 МиБ сохранил точные байты с правами 0400 для RPM и 0500 для
Setup. Проверку Setup завершили на границе передачи управления. RPM и
подписанный установщик в этой проверке не запускали.

Исправление находится в исходниках режима DEVELOP и потребует нового
отдельно квалифицированного комплекта. Квитанция .274 относится к её
исходным подписанным байтам.

Для исправления нужен маршрут ALT native Setup. RPM содержит привязку к
SHA-256 конкретного Setup, поэтому новый бинарь требует нового подписанного
комплекта с согласованной парой RPM. Изменения Windows CI относятся к
подготовке среды проверок. Для них отдельный Core или Full Setup не требуется.

## Проверка явного запуска сборки

На Windows команда `qualify-build --execute` вызвала штатный сборщик Core ZIP
для синтетического `pc_agent.exe` из чистого временного Git-репозитория.
Проверены встроенный контракт и совпадение SHA‑256 ZIP с квитанцией. Launcher
ниже минимума остановил сборку до создания выходного каталога. Ошибка
сборщика оставила `builder.log`, а повтор успешной команды сохранил ZIP.

На ALT Workstation K 11.4 создан отдельный локальный Git-резерв, без
обращения к каталогам и общему журналу выпуска. Прогон 3.2.9001 собрал
замороженные Core, launcher, Support и Setup и остановился на отсутствующем
CMake. После переноса настройки KDE в начало сборки кандидат 3.2.9002
вернул ту же причину за 2,932 с до создания дерева RPM. В отдельной проверке
ошибка конфигурации CMake с кодом 42 завершила сборку до вызова PyInstaller.
[Квитанции ALT](C:/endpoint-platform-wix-build/release-qualify-alt-stage-20261125/alt-stage-verification.log)

Тот же вход на ALT собрал Core OTA 3.2.9003 из замороженного runtime с Git SHA
`242bff43cdd1b9342cc06fd61773f48916bf7082`. Сверены 21 830 595 байт и SHA‑256
`239184ab627992e61af4765488c6b1c388c9afac58eaf99bd61d9d78ddf3ed7f` с манифестом
и квитанцией. Доставка осталась в `HOLD` до подтверждения минимальной версии
launcher и исходного профиля. Подписание и нативные испытания этих
синтетических версий находятся за пределами прогона.
[Квитанция Core OTA](C:/endpoint-platform-wix-build/release-qualify-alt-stage-20261125/alt-core-qualification-build.json)

## Проверка подписанного ALT-комплекта перед регистрацией

В изолированном Git-журнале повторно связали исходный комплект ALT 3.2.274
с его SHA‑256 `6a674fd49cdde461d8b9a486760dfae75d6c869f3a8f53f1fadabfb538db2a87`
и ревизией `9f9dc4f17820506c2099eb9124466a24e3dde162`.
На ALT 11.4 `register-alt-native` проверил обе отсоединённые подписи, подписи
обоих RPM, общий замороженный манифест и хэш Setup из подписанного Core.
Команда вернула `verified` без подключения к БД.
[Квитанция](C:/endpoint-platform-wix-build/release-native-publisher-20261125/verified-native-registration.json)

Транспортная копия с правами `0666` была отклонена. Повтор прошёл после
ограничения прав на копии до `0600` и повторной сверки SHA‑256. В отдельной
копии изменили один байт отсоединённой подписи и записали её новый хэш в
тестовый журнал. Штатная проверка подписи остановила операцию.
[Квитанция отказа](C:/endpoint-platform-wix-build/release-native-publisher-20261125/tampered-error.log)

На той же ALT 11.4 два запуска `register-alt-native --execute` с исходным
подписанным комплектом вернули результат `registered` и один UUID
`ea9f6568-4b16-4f63-8abe-bb1363e44a6d`. В изолированной SQLite остались
одна запись реестра с точными хэшами RPM и одно событие
`linux_native_release.registered`. Ответ на повторный запуск совпал побайтно.
[Квитанция реестра](C:/endpoint-platform-wix-build/release-native-publisher-20261125/isolated-native-registry.json)

## Подготовка каталога выдачи ALT

`prepare-alt-download` на ALT 11.4 проверил оригинальный подписанный комплект
3.2.274 из того же журнала резервирования. После предпросмотра входящий
каталог остался пуст. Два параллельных запуска вернули побайтно одинаковые
отчёты об одном каталоге. В нём семь файлов с проверенными SHA‑256.
Каталог принадлежит root и имеет права `0700`, файлы имеют права `0600`.
[Отчёт о подготовленном комплекте](C:/endpoint-platform-wix-build/release-native-publisher-20261125/download-final.json)

В отдельный тестовый каталог подали ошибку `ENOSPC` после частичной записи.
Готовый каталог не появился. Повтор прошёл после снятия ошибки. Затем
изменённый файл вызвал отказ и сохранился для разбора. Обновлённая команда
регистрации подписанного комплекта в изолированной БД вернула прежний UUID.
[Квитанция испытания](C:/endpoint-platform-wix-build/release-native-publisher-20261125/isolated-alt-download.json)

## Проверка планировщика на production

Расширенный срез PostgreSQL выполнен в транзакции `READ ONLY` на схеме
`0056_context_collection_history`. Срез содержал 56 уникальных карточек.
Планировщику переданы целевые SHA-256 из квитанций Windows 3.2.276 и ALT 3.2.274.

| Цель | Обязательная проверка | Случаи HOLD | Причины, важные для выпуска |
| --- | --- | ---: | --- |
| Windows 3.2.276 | Первая регистрация | 42 | 1 native recovery, 9 ожиданий WSS, 5 групп незавершённых регистраций, 14 карточек с неполным профилем |
| ALT 3.2.274 | Первая регистрация | 29 | 8 ожиданий WSS, 1 группа незавершённой регистрации, 3 карточки с неполным профилем |

План ALT учитывает завершённую регистрацию DEB как свидетельство другого
маршрута. При отсутствии точных данных об установленной системе карточка
остаётся в HOLD. Отдельная группировка Windows 10 и Windows 11 и привязка
Console preview к SHA-256 подтверждены на тестовых данных. Опубликованные
артефакты и назначения проверка не меняла.
