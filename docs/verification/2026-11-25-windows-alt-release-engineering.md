## Результат исправления ALT Setup

Два теста воспроизвели частичный файл под итоговым именем при симуляции
`ENOSPC` после первых записанных байтов. После исправления для RPM и Setup
тесты подтвердили отсутствие итогового файла после ошибки и повторное
сохранение исходных байтов. Выборка из тестов нативного жизненного цикла,
параметров стенда, RPM и комплекта дала 143 успешных теста и 3 пропуска на
Windows.

На изолированной ALT Workstation K 11.4 проверены функции из коммитов
`88e0809a2cd6b7ccbbc646310426aebc6127c2f1` и
`3f1dc26ac0d50bab39dab4c9e04cb026f6086d54`. В приватном пространстве
монтирования tmpfs размером 64 КиБ вернула фактический `ENOSPC` при
копировании 192 КиБ. Исходный код оставил частичный конечный файл для обоих
входов. После исправления конечные пути отсутствовали. Повтор на tmpfs
размером 1 МиБ сохранил точные байты с правами 0400 для RPM и 0500 для
Setup. Проверку Setup завершили на границе передачи управления. RPM и
подписанный установщик в этой проверке не запускали.

Исправление находится в исходниках режима DEVELOP и потребует нового
отдельно квалифицированного комплекта. Квитанция .274 относится к её
исходным подписанным байтам.

Для исправления нужен маршрут ALT native Setup. RPM содержит привязку к
SHA-256 конкретного Setup, поэтому новый бинарь требует нового подписанного
комплекта с согласованной парой RPM. Изменения Windows CI относятся к
подготовке среды проверок. Для них отдельный Core или Full Setup не требуется.

## Проверка явного запуска сборки

На Windows команда `qualify-build --execute` вызвала штатный сборщик Core ZIP
для синтетического `pc_agent.exe` из чистого временного Git-репозитория.
Проверены встроенный контракт и совпадение SHA‑256 ZIP с квитанцией. Launcher
ниже минимума остановил сборку до создания выходного каталога. Ошибка
сборщика оставила `builder.log`, а повтор успешной команды сохранил ZIP.

На ALT Workstation K 11.4 создан отдельный локальный Git-резерв, без
обращения к каталогам и общему журналу выпуска. Прогон 3.2.9001 собрал
замороженные Core, launcher, Support и Setup и остановился на отсутствующем
CMake. После переноса настройки KDE в начало сборки кандидат 3.2.9002
вернул ту же причину за 2,932 с до создания дерева RPM. В отдельной проверке
ошибка конфигурации CMake с кодом 42 завершила сборку до вызова PyInstaller.
[Квитанции ALT](C:/endpoint-platform-wix-build/release-qualify-alt-stage-20261125/alt-stage-verification.log)

Тот же вход на ALT собрал Core OTA 3.2.9003 из замороженного runtime с Git SHA
`242bff43cdd1b9342cc06fd61773f48916bf7082`. Сверены 21 830 595 байт и SHA‑256
`239184ab627992e61af4765488c6b1c388c9afac58eaf99bd61d9d78ddf3ed7f` с манифестом
и квитанцией. Доставка осталась в `HOLD` до подтверждения минимальной версии
launcher и исходного профиля. Подписание и нативные испытания этих

### Квалификация и открытие выдачи

На новом одноразовом клоне прошла первая установка тех же подписанных байтов
ALT 3.2.274. В этом прогоне клиентское время сбора baseline было на 1,35 с
раньше открытия WSS. Сервер сохранил результат после открытия этой же WSS.
Проверка теперь использует серверное время записи результата и ограничивает
расхождение клиентских часов. Повтор проверки на той же установке принял два
реальных образца активности с прежними ACK1, baseline и WSS.

Защищённый издатель записал живую квалификацию
`4632570a-0b8c-4a50-aec0-8e27245ad65b` в изолированный Git-журнал с областью
`first_enrollment`. Повтор вернул ту же запись. На loopback HTTPS команда
`publish-alt-download` проверила чтение от непривилегированного пользователя,
затем сверила HEAD и GET восьми файлов, включая утверждённое руководство.

одного HTTPS-ответа отменила создание каталога. После успешной выдачи точный
повтор сохранил каталог. Повтор с подменой ответа сохранил уже опубликованные
байты. Проверены отказ в выдаче индекса каталога и отказ на `OPTIONS`.

Одноразовый клон, БД опыта и копии каталога выдачи удалены. Подписанный

## Проверка планировщика на production

Расширенный срез PostgreSQL выполнен в транзакции `READ ONLY` на схеме
`0056_context_collection_history`. Срез содержал 56 уникальных карточек.
Планировщику переданы целевые SHA-256 из квитанций Windows 3.2.276 и ALT 3.2.274.

| Цель | Обязательная проверка | Случаи HOLD | Причины, важные для выпуска |
| --- | --- | ---: | --- |
| Windows 3.2.276 | Первая регистрация | 42 | 1 native recovery, 9 ожиданий WSS, 5 групп незавершённых регистраций, 14 карточек с неполным профилем |
| ALT 3.2.274 | Первая регистрация | 29 | 8 ожиданий WSS, 1 группа незавершённой регистрации, 3 карточки с неполным профилем |

План ALT учитывает завершённую регистрацию DEB как свидетельство другого
маршрута. При отсутствии точных данных об установленной системе карточка
остаётся в HOLD. Отдельная группировка Windows 10 и Windows 11 и привязка
Console preview к SHA-256 подтверждены на тестовых данных. Опубликованные
артефакты и назначения проверка не меняла.
