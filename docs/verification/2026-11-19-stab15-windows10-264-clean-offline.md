# STAB-15. Чистая офлайн-установка 3.2.264 на Windows 10

На VM251 выполнили один штатный запуск подписанного Setup 3.2.264 с `--quiet`. Независимый полный клон снимка `147/stab15-win147-229-clean` работал под Windows 10 Enterprise Evaluation x64 `19045.2006`, с `LicenseStatus=5` и остатком льготного периода 0 минут. До запуска подтвердили текущую дату, отсутствие физических адаптеров и маршрутов по умолчанию, Endpoint MSI, служб и локальной идентичности. Образ и активацию не меняли.

Исходный снимок не содержал корпоративного корня Sosnadmin Local CA. Точный публичный корень из утверждённого deployment input, отпечаток `EFBED1F8572927112500D8A6E3437CEBB63F9E64`, добавили только в одноразовую VM251. Затем штатный Authenticode подтвердил действительные подписи и метки времени EXE и MSI. SHA-256 обоих файлов совпали с [записью кандидата](../releases/windows-3.2.264-candidate.json).

MSI завершился кодом 0. Зарегистрирован один точный MSI 3.2.264, селектор и хеш установленного Core совпали с кандидатом. Одна защищённая квитанция нативной установки зафиксировала `complete` и `startup_restored=true`. Один локальный факт установки остался в `awaiting_enrollment` без серверного номера. Внешний Setup вернул `41 / PROVISIONING_FAILED / PROVISIONING_UNEXPECTED`. Файлы идентичности и enrollment claim отсутствовали. Служба EndpointAgent осталась `Auto / Stopped` с кодом 1066, процессов Core не было.

После обычной перезагрузки сохранились точные MSI и Core, исходная квитанция установки, факт `awaiting_enrollment` и тот же результат Setup. Новых событий MsiInstaller не появилось. Проверка покрывает нативную установку и удержание до регистрации в этом профиле. Сетевая регистрация, ACK и запуск принятого Core остаются открытыми.

После сбора квитанций удалили VM251, её диск и временный носитель. Исходная VM147 осталась выключенной, её снимок сохранился. Проверены SHA-256 всех 16 файлов. Хеш индекса `32425ac6c88821f6eab78452b69c687f989bf28153a16bae7a16f439bb4c53d9`.
