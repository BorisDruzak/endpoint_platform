# STAB-15. Штатный ремонт Setup 3.2.264 на Windows 10

На изолированном клоне VM257 из `206/setup253-positive-offline` и отдельном Gateway VM258 проверили подписанный Setup 3.2.264. Использовали парную лабораторную БД, доверенный TLS и мост без внешних портов. В госте отсутствовали маршруты по умолчанию. Windows 10 Enterprise Evaluation build 19045 сообщила `LicenseStatus=5` и 0 минут льготного периода. Время сверили с синхронизированным гипервизором до подключения.

- Штатный переход 3.2.253 → 3.2.264 завершился кодом 0. Gateway принял ACK № 4 с точным MSI и новой WSS на исходной карточке.
- Когда процессы Setup и Windows Installer завершились, на клоне остановили Core и удалили запись EndpointAgent в SCM. Тот же подписанный EXE с `--quiet` восстановил службу до `Auto / Running` и вернул `10 / REPAIRED / SERVICE_RUNNING`. Gateway принял одно событие установки с нативным кодом 0 и ACK № 5. MSI, селектор, Core и байты, NTFS file ID и SDDL четырёх файлов идентичности совпали с исходными для этого ремонта.
- После обычной перезагрузки на той же карточке открылась новая WSS 3.2.264. ACK № 5 сохранился, нового установочного события не было. На новой сессии `health_v1` завершился с одним успешным результатом и снимком.

Проверен ремонт отсутствующей SCM-регистрации и обычная перезагрузка одного лабораторного профиля Windows 10. VM257, VM258, их диски, мост и временные копии удалены. Исходная VM206 осталась остановлена, VM142 продолжила работу, хеш исходного дампа совпал после очистки.
