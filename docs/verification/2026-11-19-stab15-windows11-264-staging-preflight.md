# Проверка Windows 11 перед сетевым обновлением до 3.2.264

После подтверждённой установки Core .264 на VM130 проработал около часа.
В 08:39:43 UTC он завершился с кодом 1 после записи `TRANSPORT_TERMINAL`.
ОС продолжала работать. Сведения ниже описывают установку и первые четыре
минуты связи. [Журнал последующей остановки](2026-11-20-windows11-264-vm130-transport-stop.md)

19 ноября на VM130 сверили Windows 11 Enterprise LTSC 26100.9457 x64, точный исходный MSI 3.2.205 и сохранённый адрес staging. Локальный журнал содержал доставленное событие 7. На той же карточке Console показала семь событий установки и удаления, последнее — успешная установка .205. На 12:06 по Екатеринбургу назначений обновления у устройства не было.

Один штатный запуск остановленной службы EndpointAgent вернул 0. SCM показал Running, а сервер подтвердил свежую связь с Core .205 на прежней карточке. Это подтверждает работоспособность исходного Core через реле стенда. Журнал ошибок указал `access forbidden by rule`. В конфигурации реле допущено к WSS и двум другим маршрутам. Запрос Observer отклоняется до проверки полномочий устройства приложением. В выборе полного Setup на staging отображались 3.2.205 и 3.2.204. На момент проверки 3.2.264 не назначалась и не запускалась. Для проверки целевого выпуска нужны доступ Observer к штатным маршрутам и точная запись выпуска в staging. Действующая политика общего стенда использует 3.2.205.

## Результат штатной локальной установки на VM130

В staging зарегистрирован точный кандидат 3.2.264 для учёта нативной установки, без публикации для скачивания и включения в AUTO. При первом временном открытии маршрутов Observer ответили два устройства с общего адреса реле. После второго ответа исходные правила восстановили. Оба устройства работали на .205, назначений не возникло. Для самого прогона оператор согласовал только POST `/agent/v1/installation-events`. Observer продолжал получать 403. В 12:33 по Екатеринбургу на VM130 один раз запустили подписанный Setup .264 с `--quiet`. Предпроверка и проверка подписей прошли. В 12:40:55 сервер принял событие 8, связанное с событием 7 на прежней карточке и в том же поколении. Хеш MSI совпал с записью кандидата, нативный код 0. В 12:41:12 Setup завершился с кодом 0. Локальный ACK совпал с серверным. Служба EndpointAgent осталась Running, четыре защищённых файла идентичности совпали. После ACK временное правило сняли, SHA-256 конфигурации Nginx совпал с исходным, API и Nginx работали. Проверка охватывает локальное обновление на Windows 11 Enterprise LTSC 26100.9457 x64.
