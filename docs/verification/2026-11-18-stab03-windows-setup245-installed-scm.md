# STAB-03. Штатная остановка Windows Core 3.2.245 через SCM

VM207 создана полным временным клоном выключенного снимка VM206
setup245-accepted-offline. Перед первым запуском удалён виртуальный NIC.
Конфигурация VM207 и проверка внутри гостя подтвердили отсутствие сетевого адаптера. MSI
a0f858363ee4f67f22faee2303dff6e03b3f5c4da81030e9f8d515f8bce4a0a4
и выбранный Core с source 8b1e3486b2e2d1568e94785b8ae48eecb2e13527
совпали с принятым подписанным Setup 3.2.245.

Службу остановили через `Stop-Service` и повторно запустили через `Start-Service`.
Остановка отзывчивого Core заняла 808 мс по гостевому Stopwatch.
Исходное дерево выбранного Core (PID 3484) исчезло. После повторного
запуска SCM EndpointAgent в Running/Auto, новый launcher PID 4844
и ровно один выбранный Core PID 4872 под LocalService. Сохранились байты
селектора, MSI, source, последнее доставленное событие установки seq2 и
сводный SHA-256 четырёх защищённых файлов. Сводка включает SHA-256
байтов, NTFS file ID, SDDL и длину каждого файла.

Снимок VM143 `stab206-wss-stop-fault` и отчёт в коммите `96ccee3e` подтверждают принудительную
эскалацию для 3.2.206. Исполняемый сценарий для приостановки именно
установленного Endpoint Core не найден. Упакованный тест 3.2.245
проверяет канал остановки в отдельном процессе. Принудительная
эскалация через SCM установленной 3.2.245 остаётся открытой.

VM207 штатно выключена и удалена вместе со своим диском. VM206
осталась выключена, оба исходных снимка сохранены.
