# STAB-15. Офлайн-перезагрузка Windows Setup 3.2.262

19 ноября 2026 года по Екатеринбургу проверили Windows 10 Enterprise
Evaluation в сохранённой лабораторной VM226 после принятого прямого обновления
3.2.205 → 3.2.262. Перед включением PVE подтвердил остановленную VM,
единственный текущий диск `local-lvm:vm-226-disk-1`, пустые CD-слоты
и отсутствие NIC, passthrough и дополнительных QEMU-аргументов.
Снимок `primary205-accepted-offline` сохранили.

## Наблюдение

Все времена ниже UTC 18 ноября. После исходного включения Windows
сообщила время загрузки 20:24:15.500. В 20:25:35.716 событие User32
1074 (запись 361) подтвердило один запрос обычного Restart от
`shutdown.exe`. Kernel-General зафиксировал выключение (13, запись 371)
и новую загрузку (12, запись 372). Новое Windows boot time —
20:25:43.500.

- На первом замере через QGA, через 7,6 с после загрузки, SCM уже
  показывал `EndpointAgent` и `EndpointBrowserPolicy` как Auto/Running
  с кодом 0. Точный образ Core впервые виден в следующей выборке, через
  14,3 с. Его PID 4080 и PID службы 2572 сохранились в итоговом замере
  через 72,6 с. В промежуточных выборках видны краткоживущие потомки
  PID 4080 с тем же именем образа. В устойчивых замерах через 30,5,
  50,8 и 72,6 с найден один процесс точного выбранного образа.
- BrowserPolicy оставалась Running с PID 2580 во всех доступных
  постзагрузочных выборках, включая 45,7 и 72,6 с. В отобранных
  записях SCM для компонентов Endpoint после этой загрузки событий
  не найдено. Updater остался Manual/Stopped, PID 0, Win32 1077.
  `EndpointSupportAccess` отсутствовала и до, и после Restart.
- Версия выбранного Core и установленного MSI — 3.2.262, исходник
  `8e9976fecf9cfa9ae7e88f2d820df0e93aedaf0b`. SHA-256 Core
  `2d0aae9d106d2fb18a75e2a035a8af91a5fc5c8eaf78aa2e8a3ebb6634403b91`
  и кэшированного MSI
  `c7e3fb223363b009555248a797ea09214bea3857d5ef866d4a2040d2c1544cd2`
  совпали с предыдущей приёмкой. Внутренний Core сверили побайтно,
  а подписи внешнего Setup и MSI были проверены при исходной приёмке.
- SHA-256 селектора `0f4c948c3820c0c0aed70d5643f4f71d7794b85a562a491a9602d3dfaac26baf`
  и агрегат четырёх защищённых файлов
  `06482f0e290ff4cf0338fa23680dbf4e74ea87b20f49cec549af0cf419563d18`
  неизменны. Агрегат учитывает байты, длину, NTFS file ID и SDDL.
  Исходный нативный журнал остался `accepted` seq 5, результат Setup —
  `UPDATED / SERVICE_RUNNING / 0`. В журнале доставки сохранились
  `installed / delivered` для seq 1 (.205) и seq 2 (.262).
  Новое событие установки или новый ACK при Restart не появлялись.

VM226 штатно выключили. Повторный PVE-снимок подтвердил
`status: stopped`, исходный диск, пустые CD-слоты, отсутствие
активного NIC и сохранность `primary205-accepted-offline`.
Проверка относится к обычному Restart уже принятой версии .262.
Запуск BrowserPolicy при прерванном ремонте, WSS после Restart и
работа Support требуют отдельных профилей. В этой проверке
пользовательский сеанс не открывали.

Квитанции находятся в
`C:/endpoint-platform-wix-build/stab15-win262-offline-reboot`.

`d7fa9f934384e864e4be34297ff9258af37a16e933933746d8c466ab8a45bc3f`.
