# STAB-19 — Репетиция восстановления Gateway и worker

14 ноября 2026 года. Изолированный стенд Windows 11, PostgreSQL 16.15,
Python 3.14.3 и один Uvicorn. Испытан серверный код
`643f13bf075c61c2b8584d16eac99bd4918a888b` со схемой
`0052_inventory_installation`. Для испытаний создана временная база
и синтетические устройства с уникальными учётными данными.

| Сценарий | Свидетельство | Время |
| --- | --- | ---: |
| Остановка API после разрешения старта | Остановлен Uvicorn с открытой сессией, запущен новый экземпляр приложения. Клиент с прежним ID экземпляра отправил сохранённый результат дважды и получил два точных ACK. В PostgreSQL один результат, один снимок health и одна открытая сессия. | 0,610 с от начала остановки до второго ACK |
| Потеря соединений PostgreSQL | Для временной базы запрещены новые подключения и завершены существующие backend-сессии. Сокет закрылся во время отправки результата. После возврата доступа тот же API принял повтор команды с тем же результатом. Worker отразил ошибку и продолжил планирование без рестарта. | 0,107 с до второго ACK, 0,344 с до записанного расписания от возврата доступа |
| Остановка и повторный запуск worker | Два цикла запуска и остановки. Каждый запуск обработал новое устройство, а для уже обработанного устройства повторные активные запросы не возникли. | 0,808–0,867 с суммарно за два цикла |

Таймер worker на этом стенде равен 250 мс. Измеренные интервалы относятся к
синтетическому клиенту, который переподключается сразу после возврата доступа.
Для production остаётся проверить принудительное завершение процесса API,
рестарт экземпляра PostgreSQL, обычный интервал worker, клиентский backoff
и восстановление на Linux с TLS. Репетиция восстановления из резервной
копии, проверяемый внешний backup и фактические RPO/RTO остаются отдельной
приёмкой.

```powershell
$env:ENDPOINT_TEST_POSTGRES_URL = 'postgresql://postgres@127.0.0.1:55439/postgres'
$env:ENDPOINT_STABILITY_RECOVERY = '1'
python -m pytest tests/gateway/test_stability_recovery.py -s -q --disable-warnings
```

Выделенный PostgreSQL должен слушать на loopback. Тест создаёт и удаляет
свою базу. Имя временной базы проверяется перед отключением соединений.
