## ALT 3.2.269 — отключение после старта исполнителя

На обычной команде `health_v1` пассивный наблюдатель подтвердил живой процесс
исполнителя .269 и одну запись `running` с тем же UUID, без резервирования
и готового результата. При первой попытке свидетельство устарело до решения
об отключении, и команда штатно завершилась. В следующем прогоне Gateway
поставил один запрос в очередь при отключённой сети клиента. После её
восстановления наблюдатель засвидетельствовал старт, питание клона выключили.
Верхняя оценка возраста наблюдения при отправке команды выключения — 26,51 мс.

После холодной загрузки без сети тот же UUID остался в состоянии `running`,
резервирование и очередь результатов были пусты. На новом соединении Gateway
получил ровно один `AGENT_COMMAND_OUTCOME_UNKNOWN` и ноль снимков. После ACK
очередь клиента опустела. Через 20 с повторная сверка показала тот же единственный
результат. При этом отключении .269 верно распознала ситуацию, которую .266
ранее отнесла к прерыванию до старта.

## ALT 3.2.269 — отключение после записи результата до ACK

На изолированной ALT Workstation K 11.4 с подписанной .269 одна штатная
коллекция здоровья сохранила успешный результат при разрыве связи.
До выключения питания на Gateway было ноль результатов и снимков.
После холодной загрузки с отключённой сетью в очереди остался тот же UUID
и тот же SHA-256 результата. На новом соединении той же карточки Gateway
принял один результат и один снимок. После штатного ACK очередь опустела.
В этом прогоне проверены сохранность результата и его первая доставка.
В первых двух попытках наблюдатель завершился до отключения линка.
[Первоначальные попытки](C:/endpoint-platform-wix-build/stab02-alt269-stock-275/stock-health-outbox.md) · [Проверенный прогон](C:/endpoint-platform-wix-build/stab02-alt269-stock-final/stock-power-result.md)

В отдельном нативном прогоне .269 сохранили холодный снимок клиента после
отключения питания и перед первым подтверждением. Затем Gateway принял
результат, а клиент очистил очередь. К прежнему снимку вернули только
выключенный клиент. При загрузке без сети в очереди снова находился тот же
UUID с тем же SHA-256. После подключения на новой WSS очередь опустела.
Gateway сохранил ровно один исходный результат, один снимок и одну запись
доставки. Это проверяет повторную отправку при отставании состояния клиента
от сервера. Об ACK судили по работе штатной очереди. Потеря конкретного
сетевого кадра в момент записи сервером отдельно не наблюдалась.
[Квитанция нативного прогона](C:/endpoint-platform-wix-build/stab02-alt269-client-rewind/client-disk-rewind.md)

## Отдельные проверки

В трёх процессах на точных исходниках `.269 → .183 → .269` проверили поведение штатного цикла агента через тестовый транспорт с временной SQLite. Исходная `.269` отправила результат `health_v1` в кадре 7. После отката `.183` установила соединение, отправила два heartbeat и сохранила исходный результат в очереди даже после получения ACK 7. При возврате `.269` отправила тот же UUID с тем же SHA-256 в кадре 11. ACK 7 оставил результат в очереди, ACK 11 очистил её. Повторного вызова исполнителя не было. Проверка охватывает код агента. Нативная доставка по WSS и сохранение на Gateway проверяются отдельно. [Квитанция](C:/endpoint-platform-wix-build/stab02-alt269-183-runtime-result/result.json) · [Индекс SHA-256](C:/endpoint-platform-wix-build/stab02-alt269-183-runtime-result/receipts.sha256)

На точных исходниках .183 и .267 проверили обратную совместимость в четырёх отдельных процессах на Windows с SQLite 3.53.1. Модуль .183 создал новую БД. Модуль .267 с выбранной политикой ALT записал три синтетические команды. Повторное открытие старым модулем .183 сохранило схему и все строки, включая готовый результат. После возврата .267 восстановила один исход «прервано до старта», один «исход неизвестен» и прежний успешный результат. Очередь сохранила результат при несовпадающем подтверждении и опустела после точных подтверждений. Проверка охватывает только модули хранения. [Квитанция четырёх процессов](C:/endpoint-platform-wix-build/stab02-alt-183-267-source-compat/result.json) · [Воспроизведение](C:/endpoint-platform-wix-build/stab02-alt-183-267-source-compat/verify.py)

На точном исходнике .267 прошли ещё 53 локальных теста Gateway, контрактов и исполнителя. Для нативной приёмки агент сообщает `running` при запросе разрешения. Gateway отвечает `command_start` до создания процесса. Фактический запуск требует отдельного наблюдения для того же UUID. ACK результата содержит UUID и номер сообщения. Для подтверждения повторной доставки первоначального содержимого требуется также сверить сохранённый до отключения результат с данными Gateway. Эти условия учитываются в двух оставшихся нативных сценариях. [Протокол тестов](C:/endpoint-platform-wix-build/stab15-alt267-journal/diagnostic-contract-audit/pytest.log)

На отдельной ALT 11.4 без сетевого адаптера выполнили ещё два настоящих отключения питания. Использовали только вымышленные команды в отдельной базе Btrfs, SQLite 3.53.3 из комплекта, режим DELETE/EXTRA. После первого отключения сохранилось состояние `running` со снятой отметкой резервирования. После второго в очереди сохранился точный исходный результат, подтверждения ещё не было. В обоих случаях после новой загрузки `integrity_check` вернул `ok`. Между подтверждённым commit и подтверждением остановки гостя прошло около 1,6 с. Опыт проверяет запись на диск в этих двух точках. Выбор сообщения об исходе команды и повторную доставку по WSS для .267 он не проверяет. Временная ВМ удалена. На рабочей станции три отдельных процесса завершались сразу после записи выбранного этапа в синтетическую БД. Использован точный исходник .267 с явно выбранной политикой ALT. Проверка выполнялась на временных БД с отложенным ограничением целостности.
