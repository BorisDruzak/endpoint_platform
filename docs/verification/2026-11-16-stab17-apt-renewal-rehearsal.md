openvpn-100-30 таймер endpoint-apt-expiry.timer включён и активен.

## Проверка режима продления по сроку

В 23:37 UTC на изолированных копиях тех же репозиториев проверена
команда `--renew-if-due` с GnuPG и APT 2.8.4. Пока до исходной даты
истечения оставалось более трёх дней, команда проверила оба дерева
и сохранила байты обоих InRelease. Затем для копий подготовлены
подписанные индексы с двухдневным остатком срока. Команда продлила
оба индекса на семь дней. Немедленный повтор сохранил байты новой
подписи каждого индекса. SHA-256 обоих Packages и всех восьми DEB
совпали с исходными. APT принял новые подписи и проверил скачанные
пакеты-кандидаты. Все восемь тестов упаковки прошли, включая границу
в три дня, истёкший и будущий индекс и повреждение пакета.

## Проверка публикации продлённого индекса

В 23:41 UTC на временных копиях Ubuntu noble и Debian bookworm
проверен путь от отдельного дерева подписания до команды
`--publish-renewal` в дереве публикации. Команда отклонила неверный
исходный SHA-256 в обоих каналах. Release и InRelease сохранились
побайтно. При верном SHA-256 опубликованные InRelease совпали с
подписанными кандидатами побайтно. Повтор со старым хешем отклонён.
APT 2.8.4 принял оба индекса и скачал кандидатов с опубликованными
SHA-256 из таблицы. Все восемь DEB и оба Packages сохранили хеши.
Копии и временный ключ удалены.

Прошли 16 тестов упаковки, включая смену исходного InRelease между
первой проверкой и заменой, стороннего издателя, изменения вне дат,
будущую дату и повреждённый DEB. Сроки опубликованных production
индексов остались прежними.

## Проверка подготовки подписи по расписанию

В 23:47 UTC команда `--prepare-renewal` приняла данные обоих
опубликованных каналов в изолированной копии. Свежие индексы не
потребовали подписи. При двухдневном остатке срока команда создала
подписанные InRelease в отдельных каталогах с исходными SHA-256
в именах. Повтор вернул те же файлы побайтно. Исходные Release
и InRelease до отдельного вызова публикации сохранились. После
публикации в изолированную копию APT 2.8.4 принял оба канала и скачал
два пакета с исходными SHA-256. Все восемь DEB и оба Packages сохранили
хеши. Временные файлы и ключ удалены.

Тесты охватили подготовку для обеих ОС, повтор и отсутствие записи
для свежего индекса. systemd-analyze verify принял шаблоны таймера
и сервиса, календарь показал запуски в 00:10, 06:10, 12:10 и 18:10 UTC.
На хосте издателя таймеры пока не включены. Доступное локальное
хранилище GnuPG не подтвердило наличие нужного закрытого ключа.

Для завершения STAB-17 остаются продление и публикация с действующим
ключом издателя, проверка опубликованного результата обычным APT и
подтверждение доставки предупреждения издателю. В пилотном журнале
подтверждено штатное выполнение проверки, без наступления трёхдневного
порога на момент замера.

## Проверка ключа издателя из Планировщика Windows

17 ноября в сеансе Windows учётной записи издателя задача
`EndpointAptSignerProbe-20261117` дважды подписала тестовые копии
Noble Release без запроса пароля. Второй запуск выполнен после
остановки выделенного GnuPG agent и проверки, что к нему нельзя
подключиться. Планировщик завершил задачу с кодом 0. Пароль
расшифрован через DPAPI текущего пользователя и передан GnuPG
через stdin с CRLF, как при создании ключа. Вход с одним LF
давал `Bad passphrase`.

Git for Windows GnuPG 2.4.9 с LF на конце входного файла добавил
один байт при чтении подписи Linux. Вариант без завершающего LF
на входе дал точные 650 байт исходного Release на выходе
Linux `gpgv`. Отпечаток подписанта сверён с закреплённым
`840AC80D602970C76C282E6DD02C861F8B636743`.

Задача использовала интерактивный сеанс владельца DPAPI. Успешный
запуск доказывает подписание из Планировщика при входе владельца.
Для регулярной работы ещё требуется получение и проверка текущего
зеркала перед подготовкой, а также доступность издателя без активного
сеанса или согласованный рабочий график. Одноразовая задача и
временные файлы на OpenVPN удалены.

Квитанция `scheduler-probe-receipt.json` находится в
`C:/endpoint-platform-wix-build/stab17-windows-publisher-20261117`.

`13addbb465af26a5ed5fa67e8de3433986f6c231b170b8f9b437e87e30816b32`.
