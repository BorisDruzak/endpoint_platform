# Серверный профиль Endpoint Agent

Контроллер собирает `health_v1` каждые пять минут для подключённых агентов. При заданной роли карточка устройства в консоли показывает раздел `sections.server` в профиле «Состояние».

Windows Core 3.2.193 добавляет серверный профиль и резерв WSS. Windows Core 3.2.196 добавляет роль файлового сервера для Foundation 3.2.193. [Отдельный клиент Ubuntu Server](UBUNTU_SERVER_AGENT.md) включает роль PostgreSQL начиная с 3.2.196.

| Хост | Роль | Службы | Локальные тома | Проверки приложений |
| --- | --- | --- | --- | --- |
| 192.168.100.19 | `endpoint_platform` | Endpoint API, worker, Nginx, `postgresql@16-main.service` | `/`, `/boot` | `GET http://127.0.0.1:8000/healthz`, HTTP 200 |
| 192.168.100.27 | `postgresql` | `postgresql@14-main.service` | `/` с данными кластера, `/boot` | `pg_isready` на `127.0.0.1:5432` |
| 192.168.100.30 | `openvpn` | `openvpn-server@server.service`, `openvpn-web.service` | `/`, `/boot`, `/var/lib/netctl` | Веб-панель на loopback 8088, HTTP 200 или 303, и наличие UDP-слушателя 1194 |
| 192.168.100.40 | `file_server` | `LanmanServer`, `LanmanWorkstation` | `C:\\`, `D:\\` | Loopback TCP 445 и наличие опубликованного дискового ресурса SMB |
| pve1, pve2, pve3 | `proxmox` | `pve-cluster`, `corosync`, `pvedaemon`, `pveproxy`, `pvestatd`, `pvescheduler` | `/` и настроенные хранилища Proxmox для этого узла | Локальный HTTPS API с проверкой сертификата, кворум, доступность узлов и хранилищ |

Порог предупреждения — 80%, критический — 90% или меньше минимального свободного объёма. Минимум составляет 5 ГиБ для Linux `/`, 1 ГиБ для `/boot` и 10 ГиБ для `/var/lib/netctl` и Windows-томов. Отсутствующий том и ошибку измерения видно отдельно. HTTP-проверка оценивает статус без перехода по редиректу. Проверки портов показывают наличие слушателя, а пользовательские сценарии приложения проверяются отдельно на пилоте.

1. Обновите контроллер до версии, понимающей серверный раздел. Для установки на Windows Server используйте полный Setup, квалифицированный для этой ОС и состояния установки. Перед установкой клиента Ubuntu на `192.168.100.19` проверьте свободное место с учётом распаковки и отката.
2. Задайте `ENDPOINT_AGENT_SERVER_ROLE` в окружении службы агента. На Linux добавьте отдельный systemd drop-in с `Environment=ENDPOINT_AGENT_SERVER_ROLE=<роль>` в секции `[Service]`. На Windows добавьте запись `ENDPOINT_AGENT_SERVER_ROLE=<роль>` в значение `Environment` типа `REG_MULTI_SZ` службы `EndpointAgent`, сохраняя существующие записи.
3. После согласованного перезапуска только агента запросите профиль «Состояние» в карточке устройства. Сверьте свежесть результата, службы, точки монтирования и прикладные проверки. Службы Linux должны иметь состояние `active/running`, службы Windows — `running`.
4. Для отключения роли удалите её переменную из окружения службы и перезапустите агент. Дождитесь следующего сбора, чтобы актуальный снимок вернулся к базовому набору проверок.

Перед установкой запустите распакованный Core с нужным значением `ENDPOINT_AGENT_SERVER_ROLE` и параметром `--print-server-health`. Он печатает JSON без регистрации и обращения к контроллеру. Код 2 означает отсутствующую или несовместимую роль. Код 0 означает, что снимок собран, а состояние каждой проверки находится в JSON.

На Ubuntu с DEB роль можно задать в `/etc/endpoint-agent-ubuntu/site.conf`.
Проверка PostgreSQL фиксирует готовность принимать подключения без пароля.
Проверка SMB учитывает пользовательские дисковые ресурсы и передаёт только итоговый статус.

Для Proxmox VE задайте `ENDPOINT_AGENT_SERVER_ROLE=proxmox` в
`/etc/endpoint-agent-debian/site.conf`. Служба агента запускает таймер
`endpoint-proxmox-health.timer` с минутным интервалом. Изолированный локальный
сборщик запрашивает состояние кластера и кешированные показатели хранилищ,
проверяет локальный HTTPS API и записывает только результаты в
`/run/endpoint-proxmox-health/status.json`. Код 401 при проверенном TLS
означает, что API доступен и требует входа. Через три минуты без свежего
снимка прикладные проверки показывают «Нет данных». Статус хранилища
берётся из представления текущего узла в Proxmox.

Резерв WSS задаётся через `ENDPOINT_AGENT_FALLBACK_ORIGIN` в окружении службы. Резервный HTTPS-адрес должен вести к тому же Gateway, использовать тот же реестр устройств и предъявлять сертификат, доверенный агентом. При сетевой недоступности основного адреса агент пробует резерв в том же цикле подключения. Отказ в авторизации, ошибка сертификата или несовместимость протокола завершают попытку. При следующем переподключении первым снова проверяется основной адрес.

`endpoint-staging.sosnadmin.local` служит для приёмки с идентичностью staging, `endpoint.sosnadmin.local` для production с собственной идентичностью. Для Windows канал обновлений и отката проходит через подписанный Full Setup и отдельный HTTPS-контроллер обновления. Перед производственной установкой проверьте подписи, применимость к точному исходному состоянию Windows, запуск службы, все профили контекста и штатную компенсацию.
