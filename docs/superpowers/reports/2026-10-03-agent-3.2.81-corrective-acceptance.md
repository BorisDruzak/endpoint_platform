## Ownership handoff ruling and operational limitation

Installing MSI over the identical ZIP81 payload leaves both public provenance records. Canonical preflight correctly rejected mixed provenance. **Ruling:** retire the superseded ZIP records only after verifying active canonical MSI product, component GUID, source/version, receipt identity, all 2543 payload file sizes/hashes and exact 2546-file inventory. Cost if wrong: evidence could be misclassified; both original records were archived in protected backup, and runtime bytes were unchanged. Service was stopped during archival, then restarted. Final canonical preflight returned READY.

This operator handoff is documented in the runbook and is **not automatic in MSI81 or its wrapper**. A clean MSI installation has no old ZIP receipt. A future fleet procedure must include this verified step or implement automatic ownership transfer in a new immutable release. Never delete conflicting metadata without complete identity/payload verification.
