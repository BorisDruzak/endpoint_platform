# Windows. Подтверждение остановки Core перед сменой версии

В упакованном 3.2.253 координатор вернул успех при принудительной остановке до того, как Windows сообщила о завершении двух процессов тестового дерева. В этом опыте updater не менял селектор. Штатная остановка отзывчивого установленного Core через SCM прошла. [Наблюдения](../../verification/2026-11-18-stab02-windows-setup253-power-ack.md)

При неизвестном завершении сохраняются текущие байты селектора и исходная операция обновления. Пользователь разрешил штатную повторную проверку после обычной перезагрузки. Автоматическая перезагрузка и расширение полномочий оператора в этот механизм не входят.

## Служба и updater

- [x] До запуска Core зарегистрировать владельца и точный селектор в защищённом локальном состоянии. Сопоставлять владельца с конкретной загрузкой ОС и запуском службы. Прерывание между резервированием и запуском оставляет неопределённый результат.
- [x] Подтвердить завершение процессов данного Job по дескрипторам и данным самого Job. Ограничить работу и ресурсы слежения. При неполном составе, таймауте или ошибке сохранить неопределённость. Последующий запуск службы в ту же загрузку сохраняет сведения о прежнем неподтверждённом владельце.
- [x] На путях применения, восстановления и отката сопоставить исходную операцию, прежние байты селектора и владельца. Короткая общая блокировка сериализует резервирование нового Core с окончательной проверкой и заменой селектора. Долгие вызовы SCM выполняются вне этой блокировки.
- [x] Отложенное обновление сохраняет pending и доказательства состояния для повтора. В следующую подтверждённую загрузку повторно проверить исходную операцию и всех актуальных владельцев. Нормальное обновление и откат должны работать в текущую загрузку при достаточных доказательствах.

## Приёмка

- [x] Тесты Windows охватывают штатное дерево с потомком, принудительное завершение, повторный PID, отсутствующее или устаревшее свидетельство, ошибку остановки, SCM 1062 и смену владельца. Проверить неизменность селектора и операции при неопределённом исходе, повторное применение после настоящей перезагрузки и отсутствие автоматического запроса перезагрузки.
- [x] Прогнать Windows release gate на точном source, собрать отдельный подписанный кандидат и проверить его байты. На изолированной Windows проверить нормальное обновление, отложенную смену версии и повтор после обычной перезагрузки. Приёмку документировать по фактическому source и установленным артефактам.

На упакованном launcher 3.2.255 проверены штатная и принудительная остановка собственного дерева по двум дескрипторам. На установленном 3.2.259 подтверждены удержание и повтор после обычной перезагрузки. В офлайн-ветви updater после тайм-аута восстановил 3.2.259 в той же загрузке. Прямой переход 3.2.259 → 3.2.260 на VM220 прошёл в одной загрузке Windows при заранее подтверждённом владельце. Клиент сам повторил прерванную передачу.
