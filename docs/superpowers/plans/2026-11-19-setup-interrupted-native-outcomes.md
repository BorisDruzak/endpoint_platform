# Приёмка прерванных нативных операций Windows и ALT 11.4

Пользователь согласовал два правила 19 ноября. Оба относятся к следующему кандидату. Регистрацию и расширение выкладки определяет отдельная нативная приёмка конкретной пары версий.

## Windows

При межверсионном обновлении после начала исходного MSI без доказанного завершения Setup возвращает 21 и сохраняет исходную операцию. Установленная версия, состояние службы, новая загрузка и наличие кешированного пакета сами по себе исход MSI не подтверждают.

1. Воспроизвести в регрессии защищённое состояние из [прогона .192 → .263](../../verification/2026-11-19-stab15-windows-263-active-msi-power-cut.md). Проверить обычный вход Setup и обработчик восстановления при загрузке. Требуются код 21, прежние идентификаторы и байты журнала, отсутствие нового запуска MSI и переключения версии.
2. Поставить проверку до первой записи и до создания новой попытки. Проверить отдельно прерывание до начала MSI и доказанный результат, привязанный к исходной операции. Сохранить совместимость с существующими журналами.
3. После исходных тестов проверить подписанный кандидат на изолированной Windows 10. Сопоставить гостевые записи Windows Installer, код обработчика загрузки, состояние служб и защищённый журнал исходной операции. Проверку сетевого перехода с .205 учитывать отдельно.

## ALT 11.4

До подтверждения установки должны быть записаны на диск файлы пакетов, база RPM и селектор. При ошибке записи Setup сохраняет ту же операцию с кодом 21. После обычной перезагрузки завершение допускается только при успешной записи и полной проверке обоих RPM и идентичности. Повторный RPM исключён.

1. В тестах координатора вызвать ошибку записи после нативного кода 0. Проверить исходную операцию, отсутствие нового установочного события и возможность запуска штатного `reconcile` в той же загрузке без повторной установки или отправки события.
2. Проверить восстановление после обычной перезагрузки при совпадении пакетов, селектора и идентичности. Повторная ошибка записи или расхождение состояния сохраняют код 21. Отдельно проверить раздельные файловые системы и старые операции.
3. После тестов проверить подписанную пару на ALT Workstation K 11.4. Для [исходного пилота .183](../../verification/2026-11-19-stab15-alt261-pilot-post-ack2-power.md) требуется отключение питания сразу после принятого события, холодная загрузка, успешный `rpm -V` обоих пакетов и новая сессия целевого Core на прежней карточке. Для ошибки записи нужны код 21 до подтверждения и завершение той же операции без повторной транзакции RPM.
