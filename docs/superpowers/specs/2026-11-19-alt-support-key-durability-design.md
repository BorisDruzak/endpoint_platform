# ALT 11.4. Запись ключей Support перед регистрацией

После аварийного выключения свежей лабораторной установки 3.2.265 служба Support не смогла запуститься. Четыре файла двух ключевых пар имели размер 0 байт. До выключения Gateway принял регистрацию и отчёт состояния. Core сохранил свою карточку и очередь команд. Точный момент потери содержимого неизвестен. [Протокол испытания](../../verification/2026-11-19-stab02-alt265-power-ack-repair.md)

## Выбранное поведение

Пользователь выбрал исправление записи ключей в следующем кандидате. Рассматривался также перенос исправления с фиксацией дефекта опубликованной .265. Для нового кандидата служба должна обращаться к Gateway за регистрацией только после проверки двух разных валидных пар и успешной записи четырёх файлов и записей их каталога на диск.

В реализации предлагается использовать штатную блокировку и правила проверки владельца, прав и типа файлов. Проверку записи проходит и повторная регистрация с сохранёнными парами. При ошибке записи регистрация останавливается до отправки запроса. Подтверждённая ошибка записи требует повторной проверки сохранности данных. Для уже зарегистрированного устройства с пустым или повреждённым файлом действует прежний порядок восстановления оператором. Диагностика содержит только код причины.

## Приёмка

Тесты проверят порядок проверки и синхронизации до обращения к Gateway, ошибку записи файла или каталога, повтор с целыми парами и удержание повреждённой зарегистрированной идентичности. Для нативной проверки на ALT Workstation K 11.4 используется подписанный кандидат и изолированная лабораторная БД. После первой принятой регистрации с выключенным доступом фиксируются размеры файлов и отпечатки открытых ключей. Затем питание одноразового клона отключается до штатного завершения работы. После загрузки проверяются те же отпечатки, та же регистрация, новое сообщение состояния, стабильность службы, целостность обоих RPM и связь Core. Результат фиксируется для испытанного выпуска и профиля.
