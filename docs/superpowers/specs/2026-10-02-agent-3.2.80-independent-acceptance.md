# Independent Acceptance — Agent 3.2.80

This is a separate acceptance phase.

Do not treat implementation-unit tests or PR description as evidence that these scenarios work.

Use:

```text
dedicated Windows canary
real installed services
real Endpoint HTTPS/WSS
real device credential
real update rollout
exact packaged artifacts
```

No production endpoint is to be modified without explicit approval.

---

# 1. Purpose

Independently verify:

1. the previously requested WSS-independent recovery mechanism;
2. the real MSI/SCM handoff that was not fully proven for 3.2.79;
3. rollback;
4. security boundaries;
5. old 3.2.79 → new 3.2.80 compatibility;
6. previously requested Agent device/control mechanisms after update.

---

# 2. Starting state

Dedicated Windows canary must start as a **real installed 3.2.79**.

Required:

```text
EndpointAgent service exists
EndpointAgentUpdater service exists
device credential valid
CA installed/configured
current selector = 3.2.79
WSS works before fault injection
```

Record:

```text
service names
service accounts
service start modes
current selector
reported Agent version
device_id
```

Do not expose bearer credential.

# 4. Verify device binding mechanism before update

Use the accepted Agent possession mechanism.


Verify the Agent can request:

```text

```

If the canary is already linked, verify challenge issuance only or use isolated test identity according to existing policy.

This protects the previously requested Agent-registration/device-binding functionality.

# 5. Scenario A — old 3.2.79 legacy channel → stable 3.2.80

This is mandatory.

Create/register:

```text
3.2.80
platform = windows_amd64
channel = stable
```

Assign it explicitly ONLY to the canary.

Confirm that the installed 3.2.79 still makes its legacy request effectively containing:

```text
channel=canary
```

The compatible server must nevertheless return:

```text
3.2.80
channel=stable
```

This is the proof that server-owned channel selection works.

If it returns 204:

```text
FAIL
```

Do not work around it by re-registering the release as canary.

# 26. Upgrade-required compatibility

Test two clients against the new server behavior.

## 3.2.79

No `endpoint.recovery-update.v2`.

If below configured minimum:

```text
protocol-incompatible recoverable close
HTTPS supervisor continues
```

## 3.2.80

Advertises:

```text
endpoint.recovery-update.v2
```

Server may use:

```text
agent_upgrade_required
```

Client enters:

```text
CONTROL_DEGRADED_RECOVERABLE
```

and keeps update supervisor alive.

Neither should become a healthy online session while explicitly below minimum.
