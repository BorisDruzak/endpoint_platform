# Agent 3.2.81 corrective release

User approved the corrective approach with `делай` and `продолжай`: separate networkless updater, a new immutable release identity, migration from79 and repeat installed Windows acceptance. Existing production/canary authorization remains scoped to101.120; no fleet rollout/main merge.

## Design

Keep the existing offline updater algorithm, protected pending paths, LocalSystem identity, demand start, service SID/DACL and WSS startup proof. Build `endpoint-agent-updater.exe` from a dedicated entry point and spec, rather than the shared service launcher. MSI owns that binary and registers EndpointAgentUpdater against it; EndpointAgent keeps its existing launcher. The updater spec excludes network client, socket/TLS and asynchronous transport modules; both analysis-time and post-build archive inspection fail if forbidden modules/binaries remain. A harmless packaged self-check verifies imports without running the worker.

The networked Agent remains the only authenticated HTTPS/WSS actor. Runtime WFP observation must separately corroborate zero updater traffic. Packaging checks must cover the new MSI component, service executable and release sidecar. Existing79/80 identities remain unchanged.

## Compatibility and acceptance

An unchanged79 parser cannot consume stable assignments. Publish81 once with channelcanary and target only the authorized canary for the compatibility bridge. Do not re-register80 ascanary or replace any immutable build. Complete the real79→81 upgrade with source-bound candidate/WSS confirmation and actual applied report. The old MSI worker used during this bridge remains a separately identified legacy host; ZIP cannot update fixed MSI-owned service binaries. Install canonical MSI81 to transition fixed service hosts, then statically inspect and exercise the new dedicated worker through real SCM and rollback. Report this distinction; never claim an old host passed the new static gate.

Use an independently identified negative fixture for rollback. Restore all fault routes, version floors, credentials, CA, audit settings and temporary tasks. Preserve protected backups and deliver an acceptance matrix with actual evidence. If any mandatory gate fails, report NOT READY and do not publish to the fleet.

## Release verification

Source regression tests, complete local provider/Agent tests, frozen source CI, canonical stage tree/ZIP/MSI sidecar binding and strict archive scan precede release registration. A final source review and real installed-service checks follow. No hidden TLS bypass, anonymous recovery or HTTP command fallback.
