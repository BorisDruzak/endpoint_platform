# Автоматическая доставка события принятого обновления Windows

На Windows 11 VM130 локальный Setup .271 завершил обновление с .264 с кодом 0. После временной недоступности маршрута установки событие № 9 осталось в журнале. Отдельный запуск штатной доставки передал исходное событие и получил ACK 9 на прежней карточке. Оператор выбрал автоматическую доставку для следующего кандидата.

## Поведение

После штатного принятия межверсионного Full Setup на зарегистрированном устройстве Windows обеспечивает повторную отправку сохранённого события `installed`, если Gateway ещё не подтвердил его. Основание — завершение именно этой операции, её локальный результат MSI и сохранённая привязка события к устройству. Это относится к запуску Setup локально и через Console.

Используется существующая задача доставки с фиксированным действием, защищённым кэшем и проверкой ключевых полей ACK. Она переживает обычную перезагрузку и возобновляет отправку после восстановления связи. Повторы используют исходные идентификатор события, поколение и номер в существующей очереди. Подтверждение прежнего события, ответ другой карточки или ошибка транспорта оставляют ожидающую запись. После подтверждения и опустошения очереди штатная задача снимается.

Код успешной установки сохраняется. Повторная доставка выполняет только отправку уведомлений. MSI, переключение версии, регистрация устройства и активация Support имеют собственные условия. При неизвестном исходе MSI сохраняется исходное удержание операции. Конфликт с посторонней задачей оставляет её на месте и фиксируется в диагностике.

## Приёмка

На изолированном зарегистрированном Windows-клиенте обычное обновление завершается, пока маршрут приёма события недоступен. После перезагрузки и возврата маршрута Gateway должен автоматически принять исходную запись на той же карточке. Проверяются идентичность, номер и ID события, одна запись в БД, прекращение повторов после ACK и отсутствие повторного MSI. Автоматические тесты покрывают уже полученный ACK, потерю ответа после записи на сервере, чужой ACK, удержание неизвестного результата и конфликт с задачей. Прогон должен различать успешную установку и доставку уведомления.
