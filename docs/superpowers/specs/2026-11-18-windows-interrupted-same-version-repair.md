# Windows Setup. Повтор после прерванного ремонта той же версии

На Windows 10 во время ремонта 3.2.259 питание отключили после перехода защищённой записи в `msi-executing`. После загрузки один запуск подписанного Setup вернул 21. В журнале Windows Installer появились две пары событий завершения, по которым невозможно установить число запусков MSI. В этой версии обёртка может передать `REINSTALL=ALL` при наличии установленного продукта и прежней записи операции.

Пользователь согласовал ранний выход 21 для следующего кандидата. Если сохранённые данные исходной операции подтверждают отдельный ремонт той же Foundation, но исход её MSI неизвестен, штатный повтор должен вернуть 21 до нового запуска MSI. Код устанавливает вид прерванной операции по защищённой записи и исходному плану выбора версии. Наличие продукта в Windows Installer, отсутствие процесса или прошедшая перезагрузка не подтверждают результат.

Правило охватывает также ремонт прежней Foundation после отдельного обновления Core. В этом случае для определения установленной Foundation используется её защищённая запись. Повтор сохраняет исходные transaction ID, фазу, sequence, выбранный Core, состояние служб и историю установки. Продолжение допускается только по предусмотренному продуктом подтверждению исхода именно этой операции. Штатные чистая установка, обычный ремонт, составное обновление и его откат сохраняют свои условия.

На одноразовой Windows 10 проверить успешный ремонт при отсутствии незавершённой операции. В отдельном прогоне отключить питание во время фактического MSI, загрузить гостя и один раз запустить тот же подписанный Setup. Сопоставить код 21, защищённую запись, исходное состояние, квитанции Gateway и события создания процессов за всё окно повтора. При неполной трассе явно указать границу наблюдения.
