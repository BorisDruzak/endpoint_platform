# Task 13 recovery after pre-dispatch UNKNOWN

The operator authorizes a separately reviewed recovery procedure and one repeat
of seq 04, followed by STOP_BEFORE_SEQ05. This authorization does not turn an
UNKNOWN attempt into acceptance or remove a current-state predicate.

## Admission

Recovery is limited to the retained first continuation attempt, whose independently
observed root exited with code 1 and signaled native wait, during initial read-only
preflight. Require its exact reviewed closure, capsule and original prefix binding,
retained raw root streams and five observation intents/results. Reject incomplete,
timed-out or inconsistent evidence, any watchdog preparation, dispatch claim,
workload, receipt or completion, and any existing original seq04 claim. An UNKNOWN
after dispatch requires another procedure and is deliberately unsupported.

The previous retained native handle belongs to the Windows venv redirector, while
the capsule identifies its actual Python child. Pin the previous terminal witness
bytes and separately prove that exact child is gone on the same controller host,
boot and token. Native query failures remain UNKNOWN; an active matching birth
refuses recovery. For the new supervised child, select the directly pinned base
interpreter so its Popen PID/birth bind the capsule without a redirector. Keep the
existing receipt/root-completion identity equality mandatory.

Capture hashes of the protected previous evidence in a new recovery record, include
that record in the new exact source closure, and hold those original evidence files
against write/delete throughout execution. Revalidate their hashes, phase exclusions
and global claim absence immediately before launching a new root. A new root gets
a fresh continuation ID and 1200-second authority; the previous root and its UNKNOWN
remain immutable. The new actual operator message must be independently bound.

A permanent recovery-launch claim shared across continuation IDs is created
exclusively before Popen, keyed by the original seal/tip and prior failed closure.
It binds the new CID and exact closure. The child requires that same owner claim;
any new bundle after consumption refuses, including after preflight UNKNOWN.
This claim is separate from the original seq04 workload claim; neither is deleted.

## Unchanged runtime gates

Existing reconciliation, final freshness, deadline, original source/history, native
identity, watchdog, journal, raw transport, receipt and publication gates remain
mandatory. In particular, the original 14 known PID absence checks remain exact.
PID reuse explains a refusal but does not authorize ignoring it. No termination of
unrelated processes, service restart, reboot, snapshot/configuration changes or
automatic retry is part of this procedure. If known PID absence cannot be achieved
naturally, report BLOCKED and do not dispatch seq04.

## RCA and acceptance

Distinguish source defects, directly observed current process identity and historical
identity. Historical PID reuse requires a birth/identity comparison, not merely a
different image today. Diagnostic transport success is not quiescence PASS.
Independent review must cover the recovery record, exact source closure, retained
failure evidence and RCA. Source/procedure PASS alone cannot override runtime FAIL.
After admissible repeat, require actual seq04 receipt plus native root exit proof;
stop before seq05. Otherwise preserve UNKNOWN/BLOCKED and do not invent acceptance.
